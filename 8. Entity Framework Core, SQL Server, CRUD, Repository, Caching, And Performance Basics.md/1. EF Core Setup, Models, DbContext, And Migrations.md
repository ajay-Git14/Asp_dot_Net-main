# 2. What Is EF Core?

## What

**Entity Framework Core**, also called **EF Core**, is an Object Relational Mapper from Microsoft.

It allows .NET developers to work with databases using C# classes and LINQ.

Simple meaning:

```text
EF Core helps us store and retrieve database data using C# objects.
```

---

## Why

Without EF Core, developers often write SQL manually:

```sql
SELECT * FROM Complaints WHERE ComplaintId = 5;
```

With EF Core, we can write:

```csharp
var complaint = await _context.Complaints
    .FirstOrDefaultAsync(c => c.ComplaintId == 5);
```

EF Core converts this into SQL internally.

---

## What EF Core Helps With

```text
Create database tables from C# classes
Read data from database
Insert data
Update data
Delete data
Manage relationships
Track entity changes
Run migrations
Use LINQ queries
Work with SQL Server
```

---

## Smart Society Usage

EF Core will help us manage:

```text
Complaint creation
Complaint listing
Complaint details
Complaint comments
Complaint attachments
Status history
Dashboard counts
Assignment workflow
```

---

## Example

C# entity:

```csharp
public class Complaint
{
    public int ComplaintId { get; set; }

    public string Title { get; set; } = string.Empty;

    public string Status { get; set; } = "New";
}
```

EF Core can convert this into a SQL Server table:

```text
Complaints
```

with columns:

```text
ComplaintId
Title
Status
```

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Thinking EF Core means no SQL knowledge required | SQL knowledge is still important |
| Thinking EF Core stores data automatically without DbContext | DbContext and migrations are required |
| Mixing raw SQL everywhere with EF Core without reason | Use EF Core as primary data access approach |
| Treating EF Core as magic | Understand entities, DbContext, DbSet, migrations, and queries |
| Ignoring generated SQL | Learn how EF Core translates LINQ to SQL |

---

## Interview Line

**Entity Framework Core is an ORM that allows developers to interact with relational databases using C# classes, LINQ queries, DbContext, and migrations.**

# 3. ORM Refresh

## What

ORM stands for:

```text
Object Relational Mapper
```

It maps:

```text
C# objects  ↔  Database tables
C# properties  ↔  Database columns
C# relationships  ↔  Database relationships
```

---

## Why

Applications are written in object-oriented languages like C#.

Databases store data in tables.

ORM bridges the gap between both worlds.

---

## Mapping Example

C# class:

```csharp
public class Complaint
{
    public int ComplaintId { get; set; }

    public string Title { get; set; } = string.Empty;
}
```

Database table:

```text
Complaints
```

Columns:

```text
ComplaintId
Title
```

Object:

```csharp
var complaint = new Complaint
{
    Title = "Water leakage in basement"
};
```

Database row:

```text
ComplaintId = 1
Title = Water leakage in basement
```

---

## Smart Society ORM Mapping

| C# Entity | Database Table |
|---|---|
| `Complaint` | `Complaints` |
| `ComplaintComment` | `ComplaintComments` |
| `ComplaintAttachment` | `ComplaintAttachments` |
| `ComplaintStatusHistory` | `ComplaintStatusHistories` |
| `ApplicationUser` | `AspNetUsers` |

---

## Benefits Of ORM

```text
Less repetitive SQL
Strongly typed code
LINQ support
Change tracking
Migration support
Relationship mapping
Cleaner service layer
Improved maintainability
```

---

## Caution

ORM does not remove the need for database thinking.

Learners should still understand:

```text
Tables
Columns
Primary keys
Foreign keys
Indexes
Relationships
Query performance
Transactions
```

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Thinking ORM replaces database design | Database design is still required |
| Ignoring relationships | Define navigation properties and foreign keys |
| Loading too much data accidentally | Use careful queries |
| Not understanding generated tables | Inspect database after migration |
| Not learning SQL basics | SQL remains important for debugging and performance |

# 4. Code First Approach

## What

Code First means we create C# entity classes first, then EF Core creates the database structure from those classes.

Flow:

```text
Create entity classes
↓
Create DbContext
↓
Add migration
↓
Update database
↓
SQL Server tables are created
```

---

## Why

Code First is useful when the application database is designed from the application model.

It allows developers to manage database changes through code and migrations.

---

## Smart Society Code First Example

We create entity class:

```csharp
public class Complaint
{
    public int ComplaintId { get; set; }

    public string Title { get; set; } = string.Empty;

    public string Description { get; set; } = string.Empty;
}
```

Then run:

```powershell
Add-Migration InitialSmartSocietySchema
Update-Database
```

EF Core creates:

```text
Complaints table
```

---

## Code First Benefits

```text
Database structure is version-controlled
Schema changes are tracked through migrations
C# classes become source of truth
Easy to reproduce database on another machine
Good for team collaboration
Works well with Git
```

---

## Smart Society Database Evolution

```text
Migration 1: Create Identity and Complaint tables
Migration 2: Add complaint attachments
Migration 3: Add status history
Migration 4: Add assignment fields
Migration 5: Add indexes and audit fields
```

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Changing database manually and forgetting code | Keep code and migrations aligned |
| Deleting migrations randomly | Understand migration history |
| Running Update-Database without checking migration | Review generated migration |
| Treating migration as backup | Migration is schema change, not data backup |
| Not committing migrations | Commit migration files to Git |

---

## Interview Line

**Code First is an EF Core approach where C# entity classes define the database structure, and migrations are used to create or update database tables.**

# 5. Entity Classes

## What

An entity class represents a database table.

Each object of that class represents one row in the table.

Example:

```csharp
public class Complaint
{
    public int ComplaintId { get; set; }

    public string Title { get; set; } = string.Empty;
}
```

This becomes:

```text
Complaints table
```

---

## Why

Entity classes represent business data in code.

For Smart Society, core entities are:

```text
Complaint
ComplaintComment
ComplaintAttachment
ComplaintStatusHistory
```

---

## Entity Class Rules

A good entity class usually has:

```text
Primary key
Business properties
Foreign key properties
Navigation properties
Created/updated metadata where needed
```

---

## Smart Society Entity Design

### Complaint

Represents the main complaint raised by a resident.

### ComplaintComment

Represents comments or discussion on a complaint.

### ComplaintAttachment

Represents uploaded files such as issue image or proof.

### ComplaintStatusHistory

Represents timeline of status changes.

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Creating entity only for UI screen | Use ViewModel for UI, entity for database |
| Putting every property in one huge entity | Keep entities focused |
| Ignoring relationships | Add foreign keys and navigation properties |
| Not adding CreatedDate | Track important business events |
| Letting user control system fields | Set system fields server-side |

---

## Interview Line

**Entity classes represent database tables in EF Core. For Smart Society, Complaint, ComplaintComment, ComplaintAttachment, and ComplaintStatusHistory are entity classes.**

# 6. Smart Society Entity: Complaint

## What

`Complaint` is the main entity of the project.

It stores the complaint raised by a resident.

---

## Complaint Entity

Create file:

```text
Models/Complaint.cs
```

Code:

```csharp
using System.ComponentModel.DataAnnotations;
using System.ComponentModel.DataAnnotations.Schema;

namespace SmartSociety.Web.Models
{
    public class Complaint
    {
        [Key]
        public int ComplaintId { get; set; }

        [Required]
        [StringLength(100)]
        public string Title { get; set; } = string.Empty;

        [Required]
        [StringLength(1000)]
        public string Description { get; set; } = string.Empty;

        [Required]
        [StringLength(50)]
        public string Category { get; set; } = string.Empty;

        [Required]
        [StringLength(20)]
        public string Priority { get; set; } = string.Empty;

        [Required]
        [StringLength(30)]
        public string Status { get; set; } = "New";

        [Required]
        public string CreatedByUserId { get; set; } = string.Empty;

        public string? AssignedToStaffId { get; set; }

        public DateTime CreatedDate { get; set; } = DateTime.UtcNow;

        public DateTime? AssignedDate { get; set; }

        public DateTime? ResolvedDate { get; set; }

        [ForeignKey(nameof(CreatedByUserId))]
        public ApplicationUser? CreatedByUser { get; set; }

        [ForeignKey(nameof(AssignedToStaffId))]
        public ApplicationUser? AssignedToStaff { get; set; }

        public ICollection<ComplaintComment> Comments { get; set; } = new List<ComplaintComment>();

        public ICollection<ComplaintAttachment> Attachments { get; set; } = new List<ComplaintAttachment>();

        public ICollection<ComplaintStatusHistory> StatusHistory { get; set; } = new List<ComplaintStatusHistory>();
    }
}
```

---

## Property Meaning

| Property | Meaning |
|---|---|
| `ComplaintId` | Primary key |
| `Title` | Short complaint title |
| `Description` | Detailed issue explanation |
| `Category` | Plumbing, Electrical, Lift, etc. |
| `Priority` | Low, Medium, High, Critical |
| `Status` | New, Assigned, InProgress, Resolved |
| `CreatedByUserId` | Resident who created complaint |
| `AssignedToStaffId` | Staff member assigned by admin |
| `CreatedDate` | Complaint creation date |
| `AssignedDate` | Assignment date |
| `ResolvedDate` | Resolution date |
| `Comments` | Complaint timeline comments |
| `Attachments` | Uploaded files |
| `StatusHistory` | Status change timeline |

---

## Smart Society Rule

These fields should not come directly from resident form:

```text

CreatedByUserId
AssignedToStaffId
CreatedDate
AssignedDate
ResolvedDate
```

They should be set by server-side service logic.

# 10. DbContext

## What

`DbContext` is the main EF Core class that coordinates database operations.

It represents a session with the database.

Simple meaning:

```text
DbContext is the bridge between C# entities and the database.
```

---

## Why

DbContext is used to:

```text
Query data
Add records
Update records
Delete records
Track changes
Configure entity mappings
Save changes to database
```

---

## Smart Society DbContext

If Identity is already used, we should inherit from:

```csharp
IdentityDbContext<ApplicationUser>
```

Create file:

```text
Data/ApplicationDbContext.cs
```

Code:

```csharp
using Microsoft.AspNetCore.Identity.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore;
using SmartSociety.Web.Models;

namespace SmartSociety.Web.Data
{
    public class ApplicationDbContext : IdentityDbContext<ApplicationUser>
    {
        public ApplicationDbContext(DbContextOptions<ApplicationDbContext> options)
            : base(options)
        {
        }

        public DbSet<Complaint> Complaints { get; set; }

        public DbSet<ComplaintComment> ComplaintComments { get; set; }

        public DbSet<ComplaintAttachment> ComplaintAttachments { get; set; }

        public DbSet<ComplaintStatusHistory> ComplaintStatusHistories { get; set; }
    }
}
```

---

## Smart Society Mapping

| DbContext Part | Meaning |
|---|---|
| `ApplicationDbContext` | Database access class |
| `IdentityDbContext<ApplicationUser>` | Includes Identity tables |
| `DbSet<Complaint>` | Complaints table |
| `DbSet<ComplaintComment>` | ComplaintComments table |
| `DbSet<ComplaintAttachment>` | ComplaintAttachments table |
| `DbSet<ComplaintStatusHistory>` | ComplaintStatusHistories table |

# 14. Register DbContext

## What

Registering DbContext means adding it to the ASP.NET Core Dependency Injection container.

This is done in `Program.cs`.

---

## Why

Services and controllers need DbContext through DI.

EF Core also needs configuration to know which database provider and connection string to use.

---

## Program.cs Registration

```csharp
using Microsoft.EntityFrameworkCore;
using SmartSociety.Web.Data;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllersWithViews();

builder.Services.AddDbContext<ApplicationDbContext>(options =>
    options.UseSqlServer(
        builder.Configuration.GetConnectionString("DefaultConnection")));
```

---

## With Identity

```csharp
using Microsoft.AspNetCore.Identity;
using Microsoft.EntityFrameworkCore;
using SmartSociety.Web.Data;
using SmartSociety.Web.Models;

builder.Services.AddDbContext<ApplicationDbContext>(options =>
    options.UseSqlServer(
        builder.Configuration.GetConnectionString("DefaultConnection")));

builder.Services.AddIdentity<ApplicationUser, IdentityRole>()
    .AddEntityFrameworkStores<ApplicationDbContext>()
    .AddDefaultTokenProviders();
```

---

## Why AddDbContext Uses Scoped Lifetime

EF Core DbContext is normally registered as scoped.

Meaning:

```text
One DbContext instance per HTTP request
```

This fits web request operations.

---

## Smart Society Usage

Later, `ComplaintService` will inject:

```csharp
private readonly ApplicationDbContext _context;

public ComplaintService(ApplicationDbContext context)
{
    _context = context;
}
```

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Forgetting AddDbContext | DI cannot inject DbContext |
| Registering DbContext as Singleton | Use AddDbContext scoped default |
| Wrong connection string key | Match `DefaultConnection` |
| Calling UseSqlServer without package | Install SQL Server provider |
| Registering Identity before DbContext incorrectly | Configure DbContext first |

---

## Interview Line

# 15. Migrations

## What

A migration is a file generated by EF Core that describes database schema changes.

Simple meaning:

```text
Migration converts entity class changes into database changes.
```

---

## Why

When entity classes change, database tables must also change.

Migrations track these changes.

---

## Migration Flow

```text
Create/update entity classes
↓
Add migration
↓
Review migration file
↓
Update database
↓
Tables/columns are created or updated
```

---

## Add Migration Command

Using Package Manager Console:

```powershell
Add-Migration InitialSmartSocietySchema
```

Using .NET CLI:

```bash
dotnet ef migrations add InitialSmartSocietySchema
```

---

## Generated Migration Contains

```text
Up method
Down method
```

### Up Method

Defines what changes to apply.

Example:

```text
Create Complaints table
Create ComplaintComments table
```

### Down Method

Defines how to reverse changes.

Example:

```text
Drop ComplaintComments table
Drop Complaints table
```

---

## Smart Society Migration Naming

Use meaningful names:

```text
InitialSmartSocietySchema
AddComplaintAttachments
AddComplaintStatusHistory
AddComplaintAssignmentFields
AddDashboardIndexes
```

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Naming migration randomly | Use meaningful migration names |
| Not reviewing migration | Check generated schema changes |
| Changing entity but not adding migration | Add migration after model changes |
| Deleting migration after applying database | Be careful; understand migration history |
| Not committing migration files | Commit migrations to Git |

---

## Interview Line

**Migrations are EF Core files that track schema changes and allow the database structure to be created or updated from C# entity classes.**

# 17. Common Migration Errors

## Error 1: No DbContext Was Found

### Error

```text
No DbContext was found in assembly
```

### Cause

EF Core cannot find `ApplicationDbContext`.

### Fix

Check:

```text
ApplicationDbContext exists
It inherits from DbContext or IdentityDbContext
Constructor has DbContextOptions
Project builds successfully
Correct project selected in Package Manager Console
```

---

## Error 2: Unable To Resolve Service For DbContextOptions

### Cause

DbContext constructor may be wrong.

### Correct Constructor

```csharp
public ApplicationDbContext(DbContextOptions<ApplicationDbContext> options)
    : base(options)
{
}
```

---

## Error 3: Keyword Not Supported Or Login Failed

### Cause

Connection string issue.

### Fix

Check:

```text
Server name
Database name
Authentication
SQL Server service
TrustServerCertificate
Escaping backslash in JSON
```

---

## Error 4: Build Failed

### Cause

Project has compile errors.

### Fix

Run build first:

```text
Build → Build Solution
```

Fix all compile errors before migration.

---

## Error 5: The Entity Type Requires A Primary Key

### Cause

Entity class has no key.

### Fix

Add key:

```csharp
[Key]
public int ComplaintId { get; set; }
```

or follow EF convention:

```text
ClassNameId
Id
```

---

## Error 6: Multiple Cascade Paths

### Cause

SQL Server may reject multiple cascade delete paths caused by relationships.

### Fix

Configure delete behavior manually in `OnModelCreating`.

Example:

```csharp
protected override void OnModelCreating(ModelBuilder builder)
{
    base.OnModelCreating(builder);

    builder.Entity<Complaint>()
        .HasOne(c => c.CreatedByUser)
        .WithMany()
        .HasForeignKey(c => c.CreatedByUserId)
        .OnDelete(DeleteBehavior.Restrict);

    builder.Entity<Complaint>()
        .HasOne(c => c.AssignedToStaff)
        .WithMany()
        .HasForeignKey(c => c.AssignedToStaffId)
        .OnDelete(DeleteBehavior.Restrict);
}
```

---

## Error 7: Migration Already Exists

### Cause

Same migration name was used earlier.

### Fix

Use a new migration name:

```powershell
Add-Migration AddComplaintEntities
```

# 21. Common Mistakes

| Mistake | Why It Is Wrong | Correction |
|---|---|---|
| Using ViewModel as database entity | ViewModels are for UI forms | Create entity classes |

# 2. Create Operation

## What

Create operation inserts a new record into the database.

In EF Core, create usually means:

```text
Create entity object
Add it to DbSet
Call SaveChangesAsync
```

---

## Why

Residents need to create new complaints.

Example complaint:

```text
Title: Lift not working
Description: Tower B lift is not working since morning
Category: Lift
Priority: High
Status: New
```

This complaint should be saved permanently in the database.

---

## Smart Society Create Flow

```text
Resident opens complaint form
↓
Resident submits form
↓
Model binding fills ComplaintCreateViewModel
↓
Controller validates ModelState
↓
Controller calls ComplaintService.CreateComplaintAsync
↓
Service creates Complaint entity
↓
EF Core inserts record into Complaints table
↓
User is redirected to complaint list/details
```

---

## ComplaintCreateViewModel

```csharp
using Microsoft.AspNetCore.Http;
using System.ComponentModel.DataAnnotations;

        [Required(ErrorMessage = "Complaint category is required.")]
        public string Category { get; set; } = string.Empty;

        [Required(ErrorMessage = "Complaint priority is required.")]
        public string Priority { get; set; } = string.Empty;

        public IFormFile? ComplaintImage { get; set; }
    }

```

---

## ComplaintService Create Method

```csharp
public async Task CreateComplaintAsync(
    ComplaintCreateViewModel model,
    string createdByUserId)
{
    var complaint = new Complaint
    {
        Title = model.Title,
        Description = model.Description,
        Category = model.Category,
        Priority = model.Priority,
        Status = "New",
        CreatedByUserId = createdByUserId,
        CreatedDate = DateTime.UtcNow

    await _context.Complaints.AddAsync(complaint);

    await _context.SaveChangesAsync();
}
```

---

## Important Security Point

Do not allow the resident to submit:

```text
Status
CreatedByUserId
AssignedToStaffId
CreatedDate
```

These must be set by the server.

---

## Controller Example

```csharp
[HttpPost]
[ValidateAntiForgeryToken]
public async Task<IActionResult> Create(ComplaintCreateViewModel model)

    {
        return View(model);

    {
        return Unauthorized();
```

## Common Mistake

| Mistake | Correction |
|---|---|

| Forgetting SaveChangesAsync | Record will not be saved |
| Not setting CreatedByUserId | Ownership check will fail later |
| Not using anti-forgery token | Add `[ValidateAntiForgeryToken]` |

---

## Interview Line

**Create operation in EF Core means creating an entity object, adding it to a DbSet using AddAsync, and saving it to the database using SaveChangesAsync.**

# 3. AddAsync

## What

`AddAsync` adds a new entity to the DbContext so EF Core can insert it into the database.

Example:

```csharp
await _context.Complaints.AddAsync(complaint);
```

---

## Why

`AddAsync` tells EF Core:

```text
This is a new entity.
Insert it into the database when SaveChangesAsync is called.
```

---

## Important Point

`AddAsync` alone does not save the record.

This only tracks the entity as Added.

You must call:

```csharp
await _context.SaveChangesAsync();
```

---

## Smart Society Example

```csharp
var complaint = new Complaint
{
    Title = model.Title,
    Description = model.Description,
    Category = model.Category,
    Priority = model.Priority,
    Status = "New",
    CreatedByUserId = createdByUserId,
    CreatedDate = DateTime.UtcNow
};

await _context.Complaints.AddAsync(complaint);

await _context.SaveChangesAsync();
```

---

## What Happens Internally

```text
Complaint object is created
↓
AddAsync marks it as Added
↓
SaveChangesAsync generates INSERT SQL
↓
SQL Server inserts row
↓
ComplaintId is generated
```

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Calling AddAsync but not SaveChangesAsync | Always call SaveChangesAsync |
| Using AddAsync for existing entity update | Use tracked entity update pattern |
| Thinking AddAsync immediately writes database | It only prepares insert |
| Adding invalid entity | Validate before AddAsync |
| Adding duplicate entity unintentionally | Check duplicate rules where needed |

---

## Interview Line

**AddAsync marks a new entity for insertion, but the actual database insert happens only when SaveChangesAsync is called.**

---

# 4. SaveChangesAsync

## What

`SaveChangesAsync` saves all tracked changes in DbContext to the database.

Example:

```csharp
await _context.SaveChangesAsync();
```

---

## Why

EF Core tracks changes in memory first.

These changes may include:

```text
Added entities
Modified entities
Deleted entities
Relationship changes
```

`SaveChangesAsync` sends those changes to SQL Server.

---

## Smart Society Example

```csharp
complaint.Status = "Assigned";
complaint.AssignedToStaffId = staffUserId;
complaint.AssignedDate = DateTime.UtcNow;

await _context.SaveChangesAsync();
```

This updates the complaint record in SQL Server.

---

## Change Tracking Flow

```text
Entity loaded from database
↓
Property changed in C#
↓
EF Core tracks the change
↓
SaveChangesAsync generates UPDATE SQL
↓
Database is updated
```

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Forgetting SaveChangesAsync | Changes remain only in memory |
| Calling SaveChangesAsync too many times unnecessarily | Group related changes where possible |
| Not using async method | Prefer async in web applications |
| Ignoring exceptions | Handle/log database errors properly |
| Assuming SaveChangesAsync validates all business rules | Validate before saving |

---

## Interview Line

**SaveChangesAsync persists all tracked changes from DbContext to the database asynchronously.**

```csharp
public async Task<List<Complaint>> GetComplaintsForResidentAsync(string residentUserId)
{
    return await _context.Complaints
```

## Common Mistake

| Mistake | Correction |

# 6. FindAsync

## What

`FindAsync` finds an entity by primary key.

Example:

```csharp
var complaint = await _context.Complaints.FindAsync(id);
```

---

## Why

Use `FindAsync` when you know the primary key and only need the entity itself.

---

## Smart Society Example

```csharp
public async Task<Complaint?> GetComplaintByIdSimpleAsync(int complaintId)
{
    return await _context.Complaints.FindAsync(complaintId);
}
```

---

## Important Behavior

`FindAsync` can first check whether the entity is already tracked in DbContext.

If tracked, it may return from memory.

If not tracked, it queries database by primary key.

---

## When To Use FindAsync

Use `FindAsync` when:

```text
You are searching by primary key
You do not need related data
You do not need complex filters
```

---

## When Not To Use FindAsync

Do not use `FindAsync` when you need:

```text
Include related data
Filter by ownership
Filter by status
Filter archived records
Complex conditions
```

For those cases, use `FirstOrDefaultAsync`.

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Using FindAsync when Include is needed | Use FirstOrDefaultAsync with Include |
| Using FindAsync without ownership check | Add authorization/ownership check |
| Assuming FindAsync filters archived records | It only finds by primary key |
| Not handling null result | Return NotFound or safe response |
| Using FindAsync with non-key fields | Use FirstOrDefaultAsync or Where |

---

## Interview Line

**FindAsync retrieves an entity by primary key and is useful for simple primary-key lookups without related data or additional filters.**

---

# 7. FirstOrDefaultAsync

## What

`FirstOrDefaultAsync` returns the first record that matches a condition, or null if no record is found.

Example:

```csharp
var complaint = await _context.Complaints
    .FirstOrDefaultAsync(c => c.ComplaintId == id);
```

---

## Why

Use `FirstOrDefaultAsync` when you need conditions beyond primary key lookup.

Examples:

```text
Complaint ID and not archived
Complaint ID and created by current resident
Complaint ID and assigned to current staff
Complaint with related comments
Complaint with attachments
```

---

## Smart Society Example: Resident Details

```csharp
public async Task<Complaint?> GetResidentComplaintDetailsAsync(
    int complaintId,
    string residentUserId)
{
    return await _context.Complaints
        .Include(c => c.Comments)
        .Include(c => c.Attachments)
        .Include(c => c.StatusHistory)
        .FirstOrDefaultAsync(c =>
            c.ComplaintId == complaintId &&
            c.CreatedByUserId == residentUserId &&
            !c.IsArchived);
}
```

---

## Smart Society Example: Admin Details

```csharp
public async Task<Complaint?> GetComplaintDetailsForAdminAsync(int complaintId)
{
    return await _context.Complaints
        .Include(c => c.CreatedByUser)
        .Include(c => c.AssignedToStaff)
        .Include(c => c.Comments)
        .Include(c => c.Attachments)
        .Include(c => c.StatusHistory)
        .FirstOrDefaultAsync(c =>
            c.ComplaintId == complaintId &&
            !c.IsArchived);
}
```

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Using FirstOrDefaultAsync without null check | Always check null |
| Forgetting ownership filter | Add CreatedByUserId or AssignedToStaffId filter |
| Loading too much related data | Include only what is needed |
| Not filtering archived records | Add `!c.IsArchived` |
| Using FirstOrDefaultAsync when SingleOrDefaultAsync is more appropriate | Understand expected uniqueness |

---

## Interview Line

**FirstOrDefaultAsync retrieves the first record matching a condition or returns null, making it useful for filtered queries and ownership checks.**

# 8. Include

## What

`Include` loads related data with the main entity.

Example:

```csharp
var complaint = await _context.Complaints
    .Include(c => c.Comments)
    .Include(c => c.Attachments)
    .FirstOrDefaultAsync(c => c.ComplaintId == id);
```

---

## Why

By default, related data may not automatically load.

If complaint details page needs comments, attachments, and status history, we must include them.

---

## Smart Society Details Page Needs

```text
Complaint basic information
Resident details
Assigned staff details
Comments
Attachments
Status history
```

---

## Include Example

```csharp
public async Task<Complaint?> GetComplaintDetailsAsync(int complaintId)
{
    return await _context.Complaints
        .Include(c => c.CreatedByUser)
        .Include(c => c.AssignedToStaff)
        .Include(c => c.Comments)
        .Include(c => c.Attachments)
        .Include(c => c.StatusHistory)
        .FirstOrDefaultAsync(c =>
            c.ComplaintId == complaintId &&
            !c.IsArchived);
}
```

---

## Include With Ordering Awareness

For collections like status history, we may later project into a ViewModel and order explicitly.

Example later:

```csharp
StatusHistory = complaint.StatusHistory
    .OrderByDescending(s => s.ChangedDate)
    .ToList()
```

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Forgetting Include and expecting related data | Use Include |
| Including too much data on list page | Use Include only where needed |
| Using Include for every query blindly | Avoid unnecessary loading |
| Not understanding N+1 query issues | Use Include/projection carefully |
| Sorting included collections incorrectly | Project to ViewModel for precise control |

---

## Interview Line

**Include is used in EF Core to eagerly load related data such as complaint comments, attachments, status history, and user details.**

# 9. Update Operation

## What

Update operation modifies an existing database record.

In EF Core, update usually means:

```text
Load existing entity
Change allowed properties
Call SaveChangesAsync
```

---

## Why

Smart Society needs update operations for:

```text
Admin changes priority
Admin assigns staff
Staff updates complaint status
Resident updates complaint before assignment
System archives complaint
```

---

## Important Rule

Never update blindly from user-submitted entity.

Bad:

```csharp
_context.Complaints.Update(complaint);
await _context.SaveChangesAsync();
```

If `complaint` came from a form, it may include fields user should not control.

---

## Safe Update Pattern

```csharp
public async Task UpdateComplaintPriorityAsync(
    int complaintId,
    string newPriority)
{
    var complaint = await _context.Complaints
        .FirstOrDefaultAsync(c => c.ComplaintId == complaintId && !c.IsArchived);

    if (complaint == null)
    {
        throw new InvalidOperationException("Complaint not found.");
    }

    complaint.Priority = newPriority;

    await _context.SaveChangesAsync();
}
```

---

## Admin Status Update

```csharp
public async Task UpdateComplaintStatusAsync(
    int complaintId,
    string newStatus,
    string changedByUserId,
    string? remarks)
{
    var complaint = await _context.Complaints
        .FirstOrDefaultAsync(c => c.ComplaintId == complaintId && !c.IsArchived);

    if (complaint == null)
    {
        throw new InvalidOperationException("Complaint not found.");
    }

    var oldStatus = complaint.Status;

    complaint.Status = newStatus;

    var history = new ComplaintStatusHistory
    {
        ComplaintId = complaint.ComplaintId,
        OldStatus = oldStatus,
        NewStatus = newStatus,
        ChangedByUserId = changedByUserId,
        ChangedDate = DateTime.UtcNow,
        Remarks = remarks
    };

    await _context.ComplaintStatusHistories.AddAsync(history);

    await _context.SaveChangesAsync();
}
```

---

## Admin Assign Staff

```csharp
public async Task AssignComplaintAsync(
    int complaintId,
    string staffUserId,
    string adminUserId)
{
    var complaint = await _context.Complaints
        .FirstOrDefaultAsync(c => c.ComplaintId == complaintId && !c.IsArchived);

    if (complaint == null)
    {
        throw new InvalidOperationException("Complaint not found.");
    }

    var oldStatus = complaint.Status;

    complaint.AssignedToStaffId = staffUserId;
    complaint.AssignedDate = DateTime.UtcNow;
    complaint.Status = "Assigned";

    var history = new ComplaintStatusHistory
    {
        ComplaintId = complaint.ComplaintId,
        OldStatus = oldStatus,
        NewStatus = "Assigned",
        ChangedByUserId = adminUserId,
        ChangedDate = DateTime.UtcNow,
        Remarks = "Complaint assigned to staff."
    };

    await _context.ComplaintStatusHistories.AddAsync(history);

    await _context.SaveChangesAsync();
}
```

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Updating entity directly from form | Load existing entity first |
| Updating all fields blindly | Update only allowed fields |
| Not checking null | Handle missing record |
| Not adding status history | Track workflow changes |
| Not checking role/ownership | Apply authorization before update |

---

## Interview Line

**Update operation should load the existing entity, modify only allowed properties, and call SaveChangesAsync. This prevents overposting and protects workflow fields.**

# 10. Delete Operation

## What

Delete operation removes a record from the database.

In EF Core, hard delete can be done using:

```csharp
_context.Complaints.Remove(complaint);
await _context.SaveChangesAsync();
```

---

## Why

Some records may need to be removed.

But in enterprise business applications, hard delete is often avoided.

For Smart Society, complaints are business records and should usually not be physically deleted.

---

## Hard Delete Example

```csharp
public async Task DeleteComplaintAsync(int complaintId)
{
    var complaint = await _context.Complaints.FindAsync(complaintId);

    if (complaint == null)
    {
        throw new InvalidOperationException("Complaint not found.");
    }

    _context.Complaints.Remove(complaint);

    await _context.SaveChangesAsync();
}
```

---

## Why Hard Delete Is Risky

Hard delete removes history.

Problems:

```text
Audit trail is lost
Resident complaint record disappears
Admin cannot review old cases
Reports become inaccurate
Related comments and attachments may be affected
Legal/compliance tracking may be lost
```

---

## Smart Society Recommendation

Use soft delete or archive.

Instead of removing complaint:

```text
Set IsArchived = true
Set ArchivedDate
Set ArchivedByUserId
```

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Hard deleting business records | Use soft delete/archive |
| Deleting without authorization | Admin-only action |
| Deleting related data accidentally | Understand relationships |
| No audit of delete/archive | Store archived info |
| Using GET for delete | Use POST with anti-forgery |

---

## Interview Line

**Delete operation physically removes data, but enterprise applications often prefer soft delete to preserve audit history and reporting accuracy.**

---

# 11. Soft Delete Concept

## What

Soft delete means marking a record as deleted or archived instead of physically removing it from the database.

---

## Why

Soft delete preserves business history.

For Smart Society, this is important because complaints are operational records.

---

## Add Soft Delete Fields

Update `Complaint` entity:

```csharp
public bool IsArchived { get; set; }

public DateTime? ArchivedDate { get; set; }

public string? ArchivedByUserId { get; set; }
```

---

## Archive Complaint Method

```csharp
public async Task ArchiveComplaintAsync(
    int complaintId,
    string archivedByUserId)
{
    var complaint = await _context.Complaints
        .FirstOrDefaultAsync(c => c.ComplaintId == complaintId && !c.IsArchived);

    if (complaint == null)
    {
        throw new InvalidOperationException("Complaint not found.");
    }

    complaint.IsArchived = true;
    complaint.ArchivedDate = DateTime.UtcNow;
    complaint.ArchivedByUserId = archivedByUserId;

    await _context.SaveChangesAsync();
}
```

---

## Query Must Exclude Archived Records

```csharp
var complaints = await _context.Complaints
    .Where(c => !c.IsArchived)
    .ToListAsync();
```

---

## Smart Society Archive Rule

```text
Resident should not hard delete complaint.
Admin may archive old or invalid complaint.
Archived complaint should not appear in normal active list.
Archived complaint can still be available for audit/reporting.
```

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Adding IsArchived but not filtering queries | Add `!c.IsArchived` |
| Allowing residents to archive any complaint | Use authorization |
| Not storing who archived | Add ArchivedByUserId |
| Not storing archive date | Add ArchivedDate |
| Calling Remove when soft delete is required | Set archive fields instead |

---

## Interview Line

**Soft delete marks a record as archived or deleted without physically removing it, preserving history for audit, reporting, and recovery.**

---

# 12. Async EF Core Queries

## What

Async EF Core queries perform database operations without blocking the request thread.

Examples:

```csharp
await _context.Complaints.ToListAsync();
await _context.Complaints.FirstOrDefaultAsync();
await _context.SaveChangesAsync();
```

---

## Why

Database operations are I/O-bound.

In web applications, async operations improve scalability because the thread is not blocked while waiting for the database.

---

## Common Async Methods

| Method | Purpose |
|---|---|
| `ToListAsync()` | Execute query and return list |
| `FirstOrDefaultAsync()` | Return first matching record or null |
| `FindAsync()` | Find by primary key |
| `AnyAsync()` | Check if record exists |
| `CountAsync()` | Count records |
| `AddAsync()` | Add new entity asynchronously |
| `SaveChangesAsync()` | Save changes asynchronously |

---

## Smart Society Example

```csharp
public async Task<List<Complaint>> GetAllComplaintsAsync()
{
    return await _context.Complaints
        .Where(c => !c.IsArchived)
        .OrderByDescending(c => c.CreatedDate)
        .ToListAsync();
}
```

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Blocking async using `.Result` | Use `await` |
| Forgetting await | Await async operation |
| Mixing sync and async randomly | Prefer async consistently |
| Using async where no async work exists | Use async for database/file/network operations |
| Not adding EF Core namespace | Add `using Microsoft.EntityFrameworkCore;` |

---

## Required Namespace

```csharp
using Microsoft.EntityFrameworkCore;
```

---

## Interview Line

**Async EF Core queries allow database operations to run without blocking server threads, improving scalability in ASP.NET Core web applications.**

# 13. Updated Complaint Entity For CRUD

To support soft delete/archive, update `Complaint` entity:

```csharp
using System.ComponentModel.DataAnnotations;
using System.ComponentModel.DataAnnotations.Schema;

namespace SmartSociety.Web.Models
{
    public class Complaint
    {
        [Key]
        public int ComplaintId { get; set; }

        [Required]
        [StringLength(100)]
        public string Title { get; set; } = string.Empty;

        [Required]
        [StringLength(1000)]
        public string Description { get; set; } = string.Empty;

        [Required]
        [StringLength(50)]
        public string Category { get; set; } = string.Empty;

        [Required]
        [StringLength(20)]
        public string Priority { get; set; } = string.Empty;

        [Required]
        [StringLength(30)]
        public string Status { get; set; } = "New";

        [Required]
        public string CreatedByUserId { get; set; } = string.Empty;

        public string? AssignedToStaffId { get; set; }

        public DateTime CreatedDate { get; set; } = DateTime.UtcNow;

        public DateTime? AssignedDate { get; set; }

        public DateTime? ResolvedDate { get; set; }

        public bool IsArchived { get; set; }

        public DateTime? ArchivedDate { get; set; }

        public string? ArchivedByUserId { get; set; }

        [ForeignKey(nameof(CreatedByUserId))]
        public ApplicationUser? CreatedByUser { get; set; }

        [ForeignKey(nameof(AssignedToStaffId))]
        public ApplicationUser? AssignedToStaff { get; set; }

        public ICollection<ComplaintComment> Comments { get; set; } = new List<ComplaintComment>();

        public ICollection<ComplaintAttachment> Attachments { get; set; } = new List<ComplaintAttachment>();

        public ICollection<ComplaintStatusHistory> StatusHistory { get; set; } = new List<ComplaintStatusHistory>();
    }
}
```

# 15. Updated ComplaintService With CRUD

```csharp
using Microsoft.EntityFrameworkCore;
using SmartSociety.Web.Data;
using SmartSociety.Web.Interfaces;
using SmartSociety.Web.Models;
using SmartSociety.Web.ViewModels;

namespace SmartSociety.Web.Services
{
    public class ComplaintService : IComplaintService
    {
        private readonly ApplicationDbContext _context;
        private readonly ILogger<ComplaintService> _logger;

        public ComplaintService(
            ApplicationDbContext context,
            ILogger<ComplaintService> logger)
        {
            _context = context;
            _logger = logger;
        }

        public async Task CreateComplaintAsync(
            ComplaintCreateViewModel model,
            string createdByUserId)
        {
            var complaint = new Complaint
            {
                Title = model.Title,
                Description = model.Description,
                Category = model.Category,
                Priority = model.Priority,
                Status = "New",
                CreatedByUserId = createdByUserId,
                CreatedDate = DateTime.UtcNow
            };

            await _context.Complaints.AddAsync(complaint);

            await _context.SaveChangesAsync();

            _logger.LogInformation(
                "Complaint created. ComplaintId: {ComplaintId}, CreatedByUserId: {CreatedByUserId}",
                complaint.ComplaintId,
                createdByUserId);
        }

        public async Task<List<Complaint>> GetComplaintsForResidentAsync(string residentUserId)
        {
            return await _context.Complaints
                .Where(c => c.CreatedByUserId == residentUserId && !c.IsArchived)
                .OrderByDescending(c => c.CreatedDate)
                .ToListAsync();
        }

        public async Task<List<Complaint>> GetAllComplaintsAsync()
        {
            return await _context.Complaints
                .Include(c => c.CreatedByUser)
                .Include(c => c.AssignedToStaff)
                .Where(c => !c.IsArchived)
                .OrderByDescending(c => c.CreatedDate)
                .ToListAsync();
        }

        public async Task<List<Complaint>> GetAssignedComplaintsAsync(string staffUserId)
        {
            return await _context.Complaints
                .Include(c => c.CreatedByUser)
                .Where(c => c.AssignedToStaffId == staffUserId && !c.IsArchived)
                .OrderByDescending(c => c.CreatedDate)
                .ToListAsync();
        }

        public async Task<Complaint?> GetComplaintDetailsAsync(int complaintId)
        {
            return await _context.Complaints
                .Include(c => c.CreatedByUser)
                .Include(c => c.AssignedToStaff)
                .Include(c => c.Comments)
                .Include(c => c.Attachments)
                .Include(c => c.StatusHistory)
                .FirstOrDefaultAsync(c =>
                    c.ComplaintId == complaintId &&
                    !c.IsArchived);
        }

        public async Task<Complaint?> GetResidentComplaintDetailsAsync(
            int complaintId,
            string residentUserId)
        {
            return await _context.Complaints
                .Include(c => c.Comments)
                .Include(c => c.Attachments)
                .Include(c => c.StatusHistory)
                .FirstOrDefaultAsync(c =>
                    c.ComplaintId == complaintId &&
                    c.CreatedByUserId == residentUserId &&
                    !c.IsArchived);
        }

        public async Task UpdateComplaintStatusAsync(
            int complaintId,
            string newStatus,
            string changedByUserId,
            string? remarks)
        {
            var complaint = await _context.Complaints
                .FirstOrDefaultAsync(c =>
                    c.ComplaintId == complaintId &&
                    !c.IsArchived);

            if (complaint == null)
            {
                throw new InvalidOperationException("Complaint not found.");
            }

            var oldStatus = complaint.Status;

            complaint.Status = newStatus;

            if (newStatus == "Resolved")
            {
                complaint.ResolvedDate = DateTime.UtcNow;
            }

            var history = new ComplaintStatusHistory
            {
                ComplaintId = complaint.ComplaintId,
                OldStatus = oldStatus,
                NewStatus = newStatus,
                ChangedByUserId = changedByUserId,
                ChangedDate = DateTime.UtcNow,
                Remarks = remarks
            };

            await _context.ComplaintStatusHistories.AddAsync(history);

            await _context.SaveChangesAsync();

            _logger.LogInformation(
                "Complaint status updated. ComplaintId: {ComplaintId}, OldStatus: {OldStatus}, NewStatus: {NewStatus}",
                complaintId,
                oldStatus,
                newStatus);
        }

        public async Task UpdateComplaintPriorityAsync(
            int complaintId,
            string newPriority)
        {
            var complaint = await _context.Complaints
                .FirstOrDefaultAsync(c =>
                    c.ComplaintId == complaintId &&
                    !c.IsArchived);

            if (complaint == null)
            {
                throw new InvalidOperationException("Complaint not found.");
            }

            complaint.Priority = newPriority;

            await _context.SaveChangesAsync();

            _logger.LogInformation(
                "Complaint priority updated. ComplaintId: {ComplaintId}, Priority: {Priority}",
                complaintId,
                newPriority);
        }

        public async Task AssignComplaintAsync(
            int complaintId,
            string staffUserId,
            string adminUserId)
        {
            var complaint = await _context.Complaints
                .FirstOrDefaultAsync(c =>
                    c.ComplaintId == complaintId &&
                    !c.IsArchived);

            if (complaint == null)
            {
                throw new InvalidOperationException("Complaint not found.");
            }

            var oldStatus = complaint.Status;

            complaint.AssignedToStaffId = staffUserId;
            complaint.AssignedDate = DateTime.UtcNow;
            complaint.Status = "Assigned";

            var history = new ComplaintStatusHistory
            {
                ComplaintId = complaint.ComplaintId,
                OldStatus = oldStatus,
                NewStatus = "Assigned",
                ChangedByUserId = adminUserId,
                ChangedDate = DateTime.UtcNow,
                Remarks = "Complaint assigned to staff."
            };

            await _context.ComplaintStatusHistories.AddAsync(history);

            await _context.SaveChangesAsync();

            _logger.LogInformation(
                "Complaint assigned. ComplaintId: {ComplaintId}, StaffUserId: {StaffUserId}",
                complaintId,
                staffUserId);
        }

        public async Task ArchiveComplaintAsync(
            int complaintId,
            string archivedByUserId)
        {
            var complaint = await _context.Complaints
                .FirstOrDefaultAsync(c =>
                    c.ComplaintId == complaintId &&
                    !c.IsArchived);

            if (complaint == null)
            {
                throw new InvalidOperationException("Complaint not found.");
            }

            complaint.IsArchived = true;
            complaint.ArchivedDate = DateTime.UtcNow;
            complaint.ArchivedByUserId = archivedByUserId;

            await _context.SaveChangesAsync();

            _logger.LogInformation(
                "Complaint archived. ComplaintId: {ComplaintId}, ArchivedByUserId: {ArchivedByUserId}",
                complaintId,
                archivedByUserId);
        }
    }
}
```

# 18. Common Mistakes

| Mistake | Why It Is Wrong | Correction |
|---|---|---|
| Returning all complaints to every user | Data privacy issue | Filter by role/ownership |
| Using hard delete for complaints | Audit history lost | Use soft delete/archive |
| Forgetting SaveChangesAsync | Database is not updated | Always call SaveChangesAsync |
| Updating entity directly from form | Overposting risk | Load entity then update allowed fields |
| Not checking null | Runtime errors | Handle missing records |
| Forgetting Include | Related data missing | Use Include where needed |
| Including too much data | Performance issue | Include only required relationships |
| Blocking async with `.Result` | Scalability issue | Use await |
| Not using anti-forgery on update/archive | CSRF risk | Add `[ValidateAntiForgeryToken]` |
| Not adding migration after soft delete fields | Database mismatch | Add migration and update database |

# 21. Short Answers

1. CRUD stands for Create, Read, Update, and Delete.
2. Create inserts a new record into the database.
3. AddAsync marks a new entity for insertion.
4. SaveChangesAsync persists tracked changes to the database.
5. Read retrieves records from the database.
6. Use FindAsync for primary-key lookup without related data.
7. Use FirstOrDefaultAsync when filters or related data are needed.
8. Include loads related data with the main entity.
9. Update modifies an existing database record.
10. Loading existing entity prevents overposting and allows controlled property updates.
11. Delete removes a record from the database.
12. Hard delete removes audit history and affects reporting.
13. Soft delete marks a record as archived/deleted without physically removing it.
14. IsArchived, ArchivedDate, and ArchivedByUserId.
15. Archived complaints should not appear in normal active lists.
16. Async EF Core queries execute database operations without blocking request threads.
17. Async calls improve scalability for I/O-bound database work.
18. To ensure residents see only their own complaints.
19. To ensure staff see only complaints assigned to them.
20. Status history creates audit trail and workflow timeline.

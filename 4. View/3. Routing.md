# 1. Understanding Routing

## What

**Routing** is the ASP.NET Core feature that matches an incoming request URL to an executable application endpoint.

For an MVC application, that endpoint is commonly a controller action.

Example request:

```text
GET /Complaints/Details/5
```

Possible selected endpoint:

```text
ComplaintsController
↓
Details(int id)
↓
id = 5
```

---

## Why

A web application may contain many controllers and action methods.

ASP.NET Core needs a clear system to decide:

```text
Which controller should handle the request?
Which action should execute?
Which values should be extracted from the URL?
Which HTTP method is allowed?
Which URL should be generated for a link or redirect?
```

Routing provides this mapping.

---

## Smart Society Example

```text
/Complaints
```

should open the complaint list.

```text
/Complaints/Create
```

should open the complaint form.

```text
/Complaints/Details/5
```

should open complaint number `5`.

```text
/complaints/status/open
```

should show open complaints.

---

## Routing Responsibilities

| Responsibility | Example |
| --- | --- |
| Match request URL | `/Complaints/Details/5` |
| Select controller | `ComplaintsController` |
| Select action | `Details` |
| Extract route value | `id = 5` |
| Apply route constraint | `id` must be an integer |
| Generate link | Create URL for complaint details |

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Thinking routing only changes URL appearance | Routing also selects executable endpoints |
| Hardcoding every URL | Use MVC URL generation helpers and Tag Helpers |
| Confusing routing with model binding | Routing selects the endpoint; model binding supplies action parameters |
| Confusing routing with authorization | Routing finds an endpoint; authorization decides whether access is allowed |

---

## Interview Line

**Routing in ASP.NET Core matches incoming request URLs to executable endpoints such as MVC controller actions and also supports URL generation for links and redirects.**

---

# 2. Endpoint Routing

## What

ASP.NET Core uses **endpoint routing**.

An endpoint is an executable request handler together with metadata.

For MVC, endpoint metadata may include:

```text
Controller and action information
Route template
HTTP method requirement
Authorization requirement
Filter metadata
Endpoint name
```

---

## Why

Endpoint routing gives ASP.NET Core one routing system that can work with:

```text
MVC controllers
Razor Pages
Minimal APIs
SignalR
Health checks
gRPC endpoints
```

In our Smart Society MVC project, we mainly use it for controller actions.

---

## Basic Pipeline

```text
Incoming HTTP request
↓
Routing middleware examines the URL
↓
A matching endpoint is selected
↓
Authorization middleware checks endpoint metadata
↓
The selected controller action executes
↓
Response returns to the browser
```

---

## Program.cs Awareness

```csharp
app.UseRouting();

app.UseAuthorization();

app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");
```

### Meaning

| Code | Purpose |
| --- | --- |
| `UseRouting()` | Participates in endpoint matching |
| `UseAuthorization()` | Applies authorization to the selected endpoint |
| `MapControllerRoute(...)` | Adds controller endpoints using a conventional route |

---

## Smart Society Flow

```text
Request: /Complaints/Details/5
↓
Routing finds ComplaintsController.Details
↓
Route value id becomes 5
↓
Authorization is checked later when security is added
↓
Details action executes
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Treating routing as a controller feature only | Routing is part of the application endpoint pipeline |
| Placing authorization before routing without understanding the pipeline | Routing must make endpoint metadata available before authorization checks |
| Forgetting to map controllers | Add `MapControllerRoute`, `MapControllers`, or area routes as required |
| Assuming every endpoint is an MVC action | Endpoint routing also supports other ASP.NET Core endpoint types |

---

## Interview Line

**Endpoint routing selects an executable endpoint and makes its metadata available to later middleware such as authorization before the endpoint executes.**

---

# 3. Conventional Routing

## What

**Conventional routing** defines URL patterns centrally, normally in `Program.cs`.

Example:

```csharp
app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");
```

The route follows a shared convention:

```text
/controller/action/id
```

---

## Why

Conventional routing is useful for MVC applications where many controllers follow a predictable URL structure.

Examples:

```text
/Home/Index
/Complaints/Index
/Complaints/Create
/Complaints/Details/5
/Dashboard/Index
```

We do not need to write a route attribute on every action.

---

## Smart Society Example

Controller:

```csharp
public class ComplaintsController : Controller
{
    public IActionResult Index()
    {
        return View();
    }

    public IActionResult Details(int id)
    {
        return View();
    }
}
```

With the default conventional route:

| URL | Controller | Action | Route Value |
| --- | --- | --- | --- |
| `/Complaints` | Complaints | Index | None |
| `/Complaints/Index` | Complaints | Index | None |
| `/Complaints/Details/5` | Complaints | Details | `id = 5` |

---

## Good Use Cases

```text
Server-rendered MVC pages
Admin screens
Resident screens
Staff screens
Standard create, list, details, and edit pages
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Believing conventional routing means no configuration | A route convention still has to be mapped |
| Creating inconsistent controller/action names | Follow clear naming conventions |
| Putting a specific route after an overly broad route | Place specific conventional routes before general routes |
| Adding route attributes without realizing the action becomes attribute-routed | Decide intentionally between conventional and attribute routing |

---

## Interview Line

**Conventional routing defines shared URL patterns centrally and is commonly used for MVC controllers that return HTML views.**

---

# 4. Default MVC Route

## What

The standard MVC route is:

```csharp
app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");
```

---

## Route Breakdown

```text
{controller=Home}
```

means:

```text
Use the controller value from the URL.
If it is missing, use Home.
```

```text
{action=Index}
```

means:

```text
Use the action value from the URL.
If it is missing, use Index.
```

```text
{id?}
```

means:

```text
The id value is optional.
```

---

## Request Mapping

| Request URL | Controller | Action | id |
| --- | --- | --- | --- |
| `/` | Home | Index | Not supplied |
| `/Home` | Home | Index | Not supplied |
| `/Home/Index` | Home | Index | Not supplied |
| `/Complaints` | Complaints | Index | Not supplied |
| `/Complaints/Details/5` | Complaints | Details | 5 |

---

## Smart Society Example

```csharp
public class ComplaintsController : Controller
{
    public IActionResult Details(int id)
    {
        ViewBag.ComplaintId = id;
        return View();
    }
}
```

Request:

```text
/Complaints/Details/5
```

Result:

```text
controller = Complaints
action = Details
id = 5
```

---

## Important Note

The `Controller` suffix is not written in the URL.

```text
ComplaintsController
```

becomes:

```text
Complaints
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Writing `/ComplaintsController/Details/5` | Use `/Complaints/Details/5` |
| Thinking `id` is always required | `{id?}` makes it optional at routing level |
| Assuming optional route means the action can safely use a non-null value | Validate required values in action logic |
| Removing default values without checking the home page | Understand how `/` is mapped |

---

## Interview Line

**The default MVC route uses `{controller=Home}/{action=Index}/{id?}`, where Home and Index are defaults and id is optional.**

---

# 5. Route Templates

## What

A **route template** describes the URL pattern that routing should match.

Example:

```text
complaints/{action=Index}/{id?}
```

A route template contains:

```text
Literal segments
Parameter segments
Default values
Optional markers
Constraints
Catch-all parameters when required
```

---

## Literal Segments

A literal segment must match the URL text.

Example:

```text
complaints/status/{status}
```

The words below are literals:

```text
complaints
status
```

---

## Parameter Segments

A parameter segment captures a value.

Example:

```text
complaints/{id}
```

Request:

```text
/complaints/25
```

Captured value:

```text
id = 25
```

---

## Smart Society Route Template

```csharp
app.MapControllerRoute(
    name: "complaint-status",
    pattern: "complaints/status/{status}",
    defaults: new
    {
        controller = "Complaints",
        action = "ByStatus"
    });
```

Request:

```text
/complaints/status/open
```

Route values:

```text
controller = Complaints
action = ByStatus
status = open
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Forgetting which parts are literals | Text outside braces is literal |
| Using different route and action parameter names accidentally | Keep names aligned or use explicit binding |
| Creating unreadable long templates | Prefer clear resource-oriented segments |
| Treating a route template as a file-system path | It is a request URL-matching pattern |

---

## Interview Line

**A route template contains literal and parameter segments that define how URL paths are matched and how route values are extracted.**

---

# 6. Route Parameters And Route Values

## What

A route parameter is a placeholder written inside braces.

Example:

```text
{id}
```

When a URL matches, routing creates a **route value**.

---

## Smart Society Example

Route:

```text
complaints/{id}
```

Request:

```text
/complaints/8
```

Route value:

```text
id = 8
```

Action:

```csharp
[HttpGet("complaints/{id}")]
public IActionResult Details(int id)
{
    return Content($"Complaint id: {id}");
}
```

Model binding supplies the route value to the `id` action parameter.

---

## Explicit FromRoute Example

```csharp
[HttpGet("complaints/{id:int}")]
public IActionResult Details([FromRoute] int id)
{
    return Content($"Complaint id: {id}");
}
```

`[FromRoute]` makes the source explicit.

For normal MVC action parameters, it is often optional because model binding can infer the route value.

---

## Multiple Parameters

```csharp
[HttpGet("societies/{societyId:int}/complaints/{complaintId:int}")]
public IActionResult Details(
    int societyId,
    int complaintId)
{
    return Content(
        $"Society: {societyId}, Complaint: {complaintId}");
}
```

Request:

```text
/societies/3/complaints/18
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Template uses `{id}` but method expects unrelated name | Use the same name or explicit `[FromRoute(Name = "id")]` |
| Assuming route values are already business-validated | Validate existence and access in the service/action |
| Passing sensitive data in route values | Use safe identifiers only |
| Using database entity directly as a route parameter | Pass identifiers or simple route values |

---

## Interview Line

**Route parameters capture URL segments as route values, and model binding can supply those values to controller action parameters.**

---

# 7. Optional Route Parameters

## What

A question mark makes a route parameter optional.

```text
{id?}
```

---

## Why

Sometimes an endpoint can work with or without an additional URL value.

Example:

```text
/Complaints/Index
/Complaints/Index/5
```

---

## Smart Society Example

```csharp
[HttpGet("complaints/page/{pageNumber:int?}")]
public IActionResult Index(int pageNumber = 1)
{
    return Content($"Page number: {pageNumber}");
}
```

Possible requests:

```text
/complaints/page
/complaints/page/2
```

---

## Nullable Parameter Example

```csharp
[HttpGet("complaints/category/{categoryId:int?}")]
public IActionResult ByCategory(int? categoryId)
{
    if (categoryId is null)
    {
        return Content("All categories");
    }

    return Content($"Category: {categoryId}");
}
```

---

## Important Rule

Route optionality and C# parameter optionality should agree.

Good:

```csharp
[HttpGet("complaints/category/{categoryId:int?}")]
public IActionResult ByCategory(int? categoryId)
```

Potentially confusing:

```csharp
[HttpGet("complaints/category/{categoryId:int?}")]
public IActionResult ByCategory(int categoryId)
```

The route says the value can be absent, but the non-nullable `int` receives its default value when no value is supplied.

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Making a route parameter optional but treating it as always present | Use nullable type or a meaningful default |
| Adding optional parameters in confusing positions | Keep optional segments near the end |
| Using optional route value for required business identity | Use a required route segment |
| Assuming `0` means not supplied | Use a nullable type when absence matters |

---

## Interview Line

**An optional route parameter uses `?`, and the action parameter should normally be nullable or have a clear default value.**

---

# 8. Default Route Values

## What

A route template can provide a default value.

Example:

```text
{controller=Home}
```

If the controller segment is absent, routing uses `Home`.

---

## Smart Society Example

```csharp
app.MapControllerRoute(
    name: "complaints",
    pattern: "complaints/{action=Index}/{id?}",
    defaults: new
    {
        controller = "Complaints"
    });
```

Possible requests:

| URL | Selected Action |
| --- | --- |
| `/complaints` | `ComplaintsController.Index` |
| `/complaints/Create` | `ComplaintsController.Create` |
| `/complaints/Details/5` | `ComplaintsController.Details(5)` |

---

## Default Inside Template

```text
complaints/{action=Index}/{id?}
```

Here:

```text
action defaults to Index
id remains optional
```

---

## Defaults Object

```csharp
app.MapControllerRoute(
    name: "open-complaints",
    pattern: "complaints/open",
    defaults: new
    {
        controller = "Complaints",
        action = "ByStatus",
        status = "Open"
    });
```

Request:

```text
/complaints/open
```

Action receives:

```text
status = Open
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Adding defaults that hide important URL meaning | Use defaults only where they improve clarity |
| Assuming defaults validate the final value | Validate business data separately |
| Creating many overlapping defaults | Keep route design predictable |
| Forgetting a more general route may also match | Review route order and generated endpoints |

---

## Interview Line

**Default route values allow routing to supply controller, action, or parameter values when those values are not present in the URL.**

---

# 9. Attribute Routing

## What

**Attribute routing** defines route templates directly on controllers and actions using attributes.

Example:

```csharp
[Route("complaints")]
public class ComplaintsController : Controller
{
    [HttpGet]
    public IActionResult Index()
    {
        return View();
    }
}
```

---

## Why

Attribute routing gives precise control over the URL for each controller or action.

It is especially useful when:

```text
The URL should not follow controller/action naming
The route represents a resource
A REST API is being created
A friendly public URL is required
A special tracking or reporting endpoint is required
```

---

## Smart Society Example

```csharp
[Route("track")]
public class ComplaintTrackingController : Controller
{
    [HttpGet("{referenceNumber}")]
    public IActionResult Track(string referenceNumber)
    {
        return Content($"Tracking: {referenceNumber}");
    }
}
```

Request:

```text
/track/CMP-2026-0001
```

---

## Important Behavior

When a route attribute is placed on a controller or action, that action becomes attribute-routed.

It is not reached through the normal conventional route for the same action.

---

## Conventional Vs Attribute Routing

| Area | Conventional Routing | Attribute Routing |
| --- | --- | --- |
| Defined in | `Program.cs` | Controller/action attributes |
| Best for | Standard MVC page conventions | Precise URLs and APIs |
| Repetition | Less attribute repetition | More explicit route definitions |
| Control | Shared pattern | Per-controller/per-action control |

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Adding `[Route]` casually and expecting the conventional URL to remain | Understand that the action becomes attribute-routed |
| Repeating the full route on every action | Use controller-level route prefixes |
| Creating inconsistent public URLs | Establish a route naming convention |
| Mixing route and business logic | Route attributes should describe request mapping only |

---

## Interview Line

**Attribute routing maps controllers and actions directly to route templates and gives precise control over public URLs.**

---

# 10. Controller-Level Attribute Routing

## What

A route placed on a controller creates a common route prefix for its actions.

Example:

```csharp
[Route("complaints")]
public class ComplaintsController : Controller
{
}
```

---

## Why

Without a controller prefix, the same text may be repeated on every action.

Repeated approach:

```csharp
[HttpGet("complaints")]
[HttpGet("complaints/{id:int}")]
[HttpPost("complaints/create")]
```

Cleaner combined approach:

```csharp
[Route("complaints")]
public class ComplaintsController : Controller
{
    [HttpGet]
    public IActionResult Index() => View();

    [HttpGet("{id:int}")]
    public IActionResult Details(int id) => View();
}
```

---

## Smart Society Example

```csharp
[Route("resident/complaints")]
public class ResidentComplaintsController : Controller
{
    [HttpGet]
    public IActionResult Index()
    {
        return View();
    }

    [HttpGet("create")]
    public IActionResult Create()
    {
        return View();
    }

    [HttpGet("{id:int}")]
    public IActionResult Details(int id)
    {
        return View();
    }
}
```

Generated routes:

```text
/resident/complaints
/resident/complaints/create
/resident/complaints/5
```

---

## Important Rule

A controller-level route makes all actions in that controller attribute-routed.

Each action still needs a matching route selector, such as:

```text
[HttpGet]
[HttpGet("create")]
[HttpPost("create")]
[Route("details/{id:int}")]
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Placing `[Route]` on controller but forgetting action selectors | Add action-level templates or HTTP verb attributes |
| Repeating the prefix in action attributes | Action templates are appended to controller prefix |
| Starting an action template with `/` unintentionally | A leading `/` creates an absolute route and ignores the controller prefix |
| Using long technical controller names in public URLs | Define a clean route prefix |

---

## Interview Line

**A controller-level route provides a common prefix that is combined with action-level route templates.**

---

# 11. Action-Level Attribute Routing

## What

An action-level route defines the URL template for one action.

```csharp
[HttpGet("details/{id:int}")]
public IActionResult Details(int id)
{
    return View();
}
```

---

## Combined Route Example

Controller prefix:

```csharp
[Route("complaints")]
```

Action route:

```csharp
[HttpGet("details/{id:int}")]
```

Final URL:

```text
/complaints/details/5
```

---

## Smart Society Example

```csharp
[Route("complaints")]
public class ComplaintsController : Controller
{
    [HttpGet]
    public IActionResult Index()
    {
        return View();
    }

    [HttpGet("create")]
    public IActionResult Create()
    {
        return View();
    }

    [HttpPost("create")]
    [ValidateAntiForgeryToken]
    public IActionResult Create(ComplaintCreateViewModel model)
    {
        return RedirectToAction(nameof(Index));
    }

    [HttpGet("details/{id:int:min(1)}")]
    public IActionResult Details(int id)
    {
        return View();
    }
}
```

---

## Absolute Route Example

```csharp
[Route("complaints")]
public class ComplaintsController : Controller
{
    [HttpGet("/public/complaint-status")]
    public IActionResult PublicStatus()
    {
        return View();
    }
}
```

Final URL:

```text
/public/complaint-status
```

The controller prefix is not used because the action template begins with `/`.

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Expecting `create` to be a complete route when controller has a prefix | Combine controller and action templates |
| Accidentally creating an absolute route | Use leading `/` only intentionally |
| Giving GET and POST form actions unrelated paths | Keep form display and submission consistent |
| Omitting HTTP verb restrictions | Prefer `[HttpGet]`, `[HttpPost]`, and other verb attributes |

---

## Interview Line

**Action-level attribute routes define an action’s route and are normally combined with the controller-level route prefix.**

---

# 12. Route Tokens

## What

Route tokens are placeholders inside attribute routes that are replaced using controller and action names.

Common tokens:

```text
[controller]
[action]
```

---

## Example

```csharp
[Route("[controller]/[action]")]
public class ComplaintsController : Controller
{
    [HttpGet]
    public IActionResult Index()
    {
        return View();
    }

    [HttpGet("{id:int}")]
    public IActionResult Details(int id)
    {
        return View();
    }
}
```

Generated routes:

```text
/Complaints/Index
/Complaints/Details/5
```

---

## Smart Society Example

```csharp
[Route("admin/[controller]/[action]")]
public class ComplaintManagementController : Controller
{
    [HttpGet]
    public IActionResult Index()
    {
        return View();
    }

    [HttpGet("{id:int}")]
    public IActionResult Assign(int id)
    {
        return View();
    }
}
```

Possible URLs:

```text
/admin/ComplaintManagement/Index
/admin/ComplaintManagement/Assign/5
```

---

## Token Replacement Rules

```text
[controller] removes the Controller suffix.
[action] uses the selected MVC action name.
```

If `[ActionName]` is used, the action token uses the action name exposed to MVC.

---

## Caution

Route tokens reduce repetition, but public URLs can change when controller or action names are renamed.

For stable public routes, explicit route text may be better.

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Writing `{controller}` inside an attribute expecting token replacement | Attribute tokens use square brackets: `[controller]` |
| Renaming an action without considering public URL changes | Use explicit stable route text when required |
| Using tokens for every public route automatically | Choose between convenience and URL stability |
| Confusing route tokens with route parameters | Tokens are replaced at startup; parameters capture request values |

---

## Interview Line

**Attribute route tokens such as `[controller]` and `[action]` are replaced with MVC controller and action names to reduce route repetition.**

---

# 13. HTTP Verb Attributes With Route Templates

## What

HTTP verb attributes can both restrict the request method and define a route template.

Examples:

```csharp
[HttpGet("create")]
[HttpPost("create")]
[HttpPut("{id:int}")]
[HttpDelete("{id:int}")]
```

---

## Why

The URL path alone may not be enough to select the correct action.

Complaint creation uses the same route for two operations:

```text
GET /complaints/create
POST /complaints/create
```

The HTTP method distinguishes the actions.

---

## Smart Society Example

```csharp
[Route("complaints")]
public class ComplaintsController : Controller
{
    [HttpGet("create")]
    public IActionResult Create()
    {
        return View();
    }

    [HttpPost("create")]
    [ValidateAntiForgeryToken]
    public IActionResult Create(ComplaintCreateViewModel model)
    {
        if (!ModelState.IsValid)
        {
            return View(model);
        }

        return RedirectToAction(nameof(Index));
    }
}
```

---

## Request Mapping

| Request | Selected Action |
| --- | --- |
| GET `/complaints/create` | GET `Create()` |
| POST `/complaints/create` | POST `Create(model)` |

---

## Important Note

A route attribute without an HTTP verb can match multiple HTTP methods unless another selector limits it.

For clarity and security, apply the expected HTTP method.

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Using `[Route("create")]` for a POST without an HTTP restriction | Use `[HttpPost("create")]` |
| Giving GET and POST different route templates unintentionally | Use the same path for the same form workflow |
| Assuming action method name determines HTTP method | Add explicit HTTP verb attributes |
| Using GET for data-changing operations | Use POST, PUT, PATCH, or DELETE as appropriate |

---

## Interview Line

**HTTP verb attributes can define both the allowed HTTP method and the action route template, enabling the same URL path to support separate GET and POST actions.**

---

# 14. Route Constraints

## What

A route constraint limits which values a route parameter can match.

Example:

```text
{id:int}
```

This route matches an integer value.

---

## Why

Constraints help routing distinguish between routes.

Example actions:

```csharp
[HttpGet("{id:int}")]
public IActionResult Details(int id)

[HttpGet("reference/{referenceNumber}")]
public IActionResult DetailsByReference(string referenceNumber)
```

Requests:

```text
/complaints/25
/complaints/reference/CMP-2026-0025
```

---

## Common Built-In Constraints

| Constraint | Example | Meaning |
| --- | --- | --- |
| `int` | `{id:int}` | Integer value |
| `guid` | `{id:guid}` | GUID value |
| `bool` | `{active:bool}` | Boolean value |
| `datetime` | `{date:datetime}` | Date-time value |
| `alpha` | `{status:alpha}` | Alphabetic characters |
| `min` | `{id:min(1)}` | Integer at least 1 |
| `max` | `{page:max(100)}` | Integer at most 100 |
| `range` | `{page:range(1,100)}` | Integer within range |
| `length` | `{code:length(6)}` | Exact string length |
| `minlength` | `{name:minlength(3)}` | Minimum string length |
| `maxlength` | `{name:maxlength(50)}` | Maximum string length |

---

## Combining Constraints

```csharp
[HttpGet("details/{id:int:min(1)}")]
public IActionResult Details(int id)
{
    return View();
}
```

The value must:

```text
Be an integer
Be at least 1
```

---

## Very Important Rule

Route constraints are used to **disambiguate route matches**.

They are not a replacement for input validation or business validation.

Example:

```text
{id:int:min(1)}
```

can reject `abc` or `0` at routing level, but it cannot confirm:

```text
The complaint exists
The user owns the complaint
The complaint belongs to the current society
The complaint is visible to this role
```

Those checks belong in action, service, and authorization logic.

---

## Route Result Example

Route:

```text
/complaints/{id:int}
```

| Request | Result |
| --- | --- |
| `/complaints/5` | Route can match |
| `/complaints/abc` | Route does not match |
| `/complaints/-2` | Matches `int` unless another constraint such as `min(1)` is added |

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Treating route constraints as complete validation | Validate business rules separately |
| Using constraints only to return a friendly validation message | Constraints usually produce route non-match behavior |
| Creating unnecessary custom constraints | Use built-in constraints first |
| Forgetting minimum/range checks | Combine constraints where route disambiguation requires them |

---

## Interview Line

**Route constraints restrict which values can match a route parameter and primarily help route disambiguation; they do not replace application validation.**

# 18. Conventional Route Order And Precedence

## What

Conventional routes are processed in the order they are registered.

More specific routes should normally be registered before more general routes.

---

## Smart Society Example

Correct order:

```csharp
app.MapControllerRoute(
    name: "complaint-status",
    pattern: "complaints/status/{status:alpha}",
    defaults: new
    {
        controller = "Complaints",
        action = "ByStatus"
    });

app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");
```

The specific complaint route appears before the default route.

---

## Why Order Matters

A broad conventional route may match a URL before a more specific route receives the opportunity.

General rule:

```text
Specific route first
General default route last
```

---

## Attribute Route Precedence

Attribute routing builds a collection of route endpoints and chooses the best match using route precedence.

Generally:

```text
Literal segments are more specific than parameter segments.
Constrained parameters are more specific than unconstrained parameters.
```

Example:

```text
/complaints/create
```

is more specific than:

```text
/complaints/{value}
```

because `create` is a literal segment.

---

## Do Not Depend On Controller File Order

The physical order of controller classes or action methods should not be used as a routing strategy.

Make routes unambiguous through:

```text
Clear literal segments
HTTP verb selectors
Route constraints
Distinct route templates
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Mapping the default conventional route before a specific custom route | Put the specific route first |
| Depending on action declaration order | Define unambiguous route templates |
| Creating many nearly identical route patterns | Simplify route design |
| Assuming attribute route order works exactly like conventional registration order | Understand route specificity and precedence |

---

## Interview Line

**Conventional route order matters, so specific routes are registered before general routes; attribute routing uses route precedence to choose the most specific candidate.**

# 19. Ambiguous Route Matches

## What

An ambiguous match occurs when routing finds multiple equally valid endpoints and cannot select one best endpoint.

ASP.NET Core can throw an `AmbiguousMatchException`.

---

## Problem Example

```csharp
[HttpGet("complaints/{value}")]
public IActionResult DetailsById(string value)
{
    return View();
}

[HttpGet("complaints/{reference}")]
public IActionResult DetailsByReference(string reference)
{
    return View();
}
```

Both routes have the same structure:

```text
complaints/{one-string-segment}
```

The parameter name does not make them different.

---

## Corrected Example

```csharp
[HttpGet("complaints/{id:int}")]
public IActionResult DetailsById(int id)
{
    return View();
}

[HttpGet("complaints/reference/{referenceNumber}")]
public IActionResult DetailsByReference(string referenceNumber)
{
    return View();
}
```

Now the routes are distinct.

---

## Smart Society Example

| Requirement | Clear Route |
| --- | --- |
| Find by numeric ID | `/complaints/25` |
| Find by public reference | `/complaints/reference/CMP-2026-0025` |
| Find by status | `/complaints/status/open` |
| Open create form | `/complaints/create` |

---

## Common Causes

```text
Same route template on two actions
Missing HTTP verb selector
Two unconstrained parameter routes
Duplicated route attributes
Overlapping custom conventional routes
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Renaming route parameters and expecting ambiguity to disappear | Parameter names do not change route shape |
| Adding arbitrary route order as the only fix | Create semantically distinct routes |
| Removing useful route constraints | Use constraints to disambiguate where appropriate |
| Giving two actions the same route and HTTP method | Change route, method, or endpoint design |

---

## Interview Line

**An ambiguous route match occurs when multiple endpoints are equally valid; it should be fixed with distinct templates, HTTP methods, literals, or constraints.**

# 22. Mixed Routing Strategy

## What

An ASP.NET Core MVC application can use conventional routing and attribute routing together.

Typical strategy:

```text
Conventional routing for standard MVC pages
Attribute routing for precise public routes or APIs
```

---

## Important Rule

An individual action is either conventionally routed or attribute-routed.

When a route attribute is added to a controller, all actions in that controller become attribute-routed.

They are not also reached through the conventional route.

---

## Smart Society Strategy

### Conventional Routing

Use for:

```text
Home pages
Standard dashboard pages
Internal MVC CRUD pages
Simple controller/action navigation
```

### Attribute Routing

Use for:

```text
Public complaint tracking
Future REST APIs
Stable externally shared URLs
Special reporting endpoints
```

---

## Example

Conventional controller:

```csharp
public class ComplaintsController : Controller
{
    public IActionResult Index()
    {
        return View();
    }
}
```

Attribute-routed controller:

```csharp
[Route("track")]
public class ComplaintTrackingController : Controller
{
    [HttpGet("{referenceNumber}")]
    public IActionResult Index(string referenceNumber)
    {
        return View();
    }
}
```

---

## Mapping Controllers

A conventional route mapping such as `MapControllerRoute` maps conventionally routed controllers and also makes attribute-routed controller endpoints available.

For an application that uses only attribute-routed controllers, `MapControllers()` can be used.

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Expecting the same action to be reached through both routing styles automatically | An action is either conventional or attribute-routed |
| Adding `[Route]` to one controller and testing only the old conventional URL | Test the actual attribute route |
| Using mixed routing without a design rule | Define when each style should be used |
| Mapping only unrelated endpoint types | Ensure controller endpoints are mapped |

---

## Interview Line

**ASP.NET Core can mix routing styles, but each action is either conventional or attribute-routed; standard MVC pages commonly use conventions while precise public or API routes use attributes.**

## 23.2 Conventional ComplaintsController

```csharp
using Microsoft.AspNetCore.Mvc;
using SmartSociety.Web.Interfaces;
using SmartSociety.Web.ViewModels;

namespace SmartSociety.Web.Controllers;

public class ComplaintsController : Controller
{
    private readonly IComplaintService _complaintService;

    public ComplaintsController(
        IComplaintService complaintService)
    {
        _complaintService = complaintService;
    }

    [HttpGet]
    public async Task<IActionResult> Index(
        string? status,
        string? search,
        int pageNumber = 1)
    {
        if (pageNumber < 1)
        {
            pageNumber = 1;
        }

        var result = await _complaintService.SearchAsync(
            status,
            search,
            pageNumber);

        return View(result);
    }

    [HttpGet]
    public IActionResult Create()
    {
        return View();
    }

    [HttpPost]
    [ValidateAntiForgeryToken]
    public async Task<IActionResult> Create(
        ComplaintCreateViewModel model)
    {
        if (!ModelState.IsValid)
        {
            return View(model);
        }

        var complaintId =
            await _complaintService.CreateComplaintAsync(model);

        TempData["SuccessMessage"] =
            "Complaint created successfully.";

        return RedirectToRoute(
            "complaint-details",
            new { id = complaintId });
    }

    [HttpGet]
    public async Task<IActionResult> Details(int id)
    {
        if (id <= 0)
        {
            return BadRequest("Invalid complaint id.");
        }

        var complaint =
            await _complaintService.GetComplaintByIdAsync(id);

        if (complaint is null)
        {
            return NotFound();
        }

        return View(complaint);
    }

    [HttpGet]
    public async Task<IActionResult> ByStatus(string status)
    {
        if (string.IsNullOrWhiteSpace(status))
        {
            return BadRequest("Status is required.");
        }

        var complaints =
            await _complaintService.GetByStatusAsync(status);

        ViewBag.SelectedStatus = status;

        return View(complaints);
    }
}
```

# 25. Common Mistakes

| Mistake | Why It Is Wrong | Correction |
| --- | --- | --- |
| Writing controller suffix in URL | MVC route uses controller name without `Controller` | Use `/Complaints`, not `/ComplaintsController` |
| Registering the default route before specific conventional routes | Broad route may be selected first | Put specific routes first |
| Adding `[Route]` and expecting conventional URL to keep working | Action becomes attribute-routed | Test the attribute route |
| Using route parameter names that do not match action parameters | Binding becomes unclear or fails | Align names or use `[FromRoute(Name = ...)]` |
| Treating route constraints as complete validation | Constraints only help matching | Validate business rules in action/service |
| Creating two equivalent parameter routes | Routing cannot select one best endpoint | Add literal segments or constraints |
| Hardcoding URLs in views | Changes become difficult | Use Tag Helpers |
| Manually concatenating redirect URLs | Fragile and error-prone | Use redirect helpers |
| Using route paths for every filter | URLs become difficult to maintain | Use query strings for optional filters |
| Using query strings for sensitive values | URLs may be logged or shared | Never expose sensitive information |
| Creating Areas without authorization | Areas only organize features | Add server-side authorization later |
| Assuming route name affects matching | Route names are for generation | Use route patterns and precedence for matching |
| Depending on action method order | Order is not a route design | Make endpoints unambiguous |
| Forgetting HTTP verb attributes | Endpoint may accept unintended methods | Add `[HttpGet]`, `[HttpPost]`, etc. |
| Making optional route values non-nullable without thought | Missing value may become a default CLR value | Use nullable types or explicit defaults |

# 28. Short Answers

1. Routing matches incoming requests to executable endpoints and supports URL generation.
2. An endpoint is an executable request handler with metadata.
3. Endpoint routing finds a matching endpoint and exposes its metadata to the pipeline.
4. Conventional routing uses centrally defined shared URL patterns.
5. It is usually configured in `Program.cs` with `MapControllerRoute`.
6. It defaults to HomeController.Index and accepts an optional id value.
7. MVC uses the controller name without the `Controller` suffix as the route value.
8. A route template describes the URL pattern to match.
9. A literal segment is fixed URL text such as `complaints` or `status`.
10. A route parameter is a placeholder such as `{id}`.
11. A route value is the value captured for a route parameter.
12. Model binding supplies route values to matching action parameters.
13. `?` makes the route parameter optional.
14. Matching nullability prevents missing route values from being mistaken for valid defaults.
15. A default route value is used when that segment or value is not supplied.
16. Attribute routing defines routes directly on controllers and actions.
17. All actions in that controller become attribute-routed.
18. The action template is appended to the controller prefix unless it is absolute.
19. An absolute action route begins with `/` or `~/` and does not combine with the controller prefix.
20. They are replaced with controller and action names.
21. Tokens are replaced when routes are built; parameters capture values from requests.
22. HTTP verb attributes distinguish the GET and POST endpoints.
23. A route constraint restricts which parameter values can match a route.
24. The id must be an integer of at least 1.
25. Constraints select routes; service and action logic validate business rules.
26. A named route has a unique logical name used for URL generation.
27. No. Route names do not affect incoming request matching.
28. Tag Helpers generate maintainable URLs from routing information.
29. It supplies an `id` route value during URL generation.
30. `RedirectToAction` targets a controller action; `RedirectToRoute` targets a named route.
31. `Url.Action` generates an action URL; `Url.RouteUrl` generates a named-route URL.
32. Specific conventional routes should be tested before broad general routes.
33. It occurs when multiple endpoints are equally valid matches.
34. Use distinct literals, HTTP verbs, constraints, or route templates.
35. Route values come from the path; query values come after `?`.
36. Query-string values are normally suitable for optional filtering, sorting, searching, and pagination.
37. Areas organize a large MVC application into functional sections.
38. No. Authorization must still be applied separately.
39. Yes. One application can use both routing styles.
40. No. An action is either conventionally routed or attribute-routed.

In my Smart Society Issue Management System, I use ASP.NET Core endpoint routing to map incoming requests to MVC controller actions.

For public complaint tracking, I use attribute routing. The controller has a track prefix, and the tracking action captures the complaint reference number from /track/{referenceNumber}. I gave this endpoint a route name so Razor views can generate tracking links without hardcoded URLs.

I use route constraints to help routing select the correct endpoint, but I do not treat constraints as business validation. The service still checks whether the complaint exists and whether the current user is allowed to access it.

For URL generation, I use Anchor Tag Helpers, RedirectToAction, RedirectToRoute, Url.Action, and Url.RouteUrl. Route values identify resources, while query strings are used for optional filtering, searching, sorting, and pagination.

# 1. Understanding Razor

## What

**Razor** is the ASP.NET Core markup syntax used to write dynamic server-rendered HTML pages.

In ASP.NET Core MVC, Razor files usually use the `.cshtml` extension.

Example file:

```text
Views/Complaints/Index.cshtml
```

A Razor View contains:

```text
HTML
C# expressions
C# code blocks
Razor directives
Tag Helpers
ViewModel access
```

---

## Why

A normal HTML file is static.

It cannot directly show dynamic values such as:

```text
Complaint title
Complaint status
Logged-in user name
Total open complaints
Conditional buttons
Validation messages
```

Razor solves this by allowing C# and HTML to work together in one View file.

---

## Smart Society Example

A complaint card may need to show values coming from the controller:

```cshtml
<h3>@Model.Title</h3>
<p>Status: @Model.Status</p>
<p>Priority: @Model.Priority</p>
```

Final rendered HTML may become:

```html
<h3>Lift not working</h3>
<p>Status: Open</p>
<p>Priority: High</p>
```

---

## Razor Responsibility

| Responsibility | Example |
| --- | --- |
| Render HTML | `<h1>Complaints</h1>` |
| Show dynamic data | `@Model.Title` |
| Apply conditions | `@if (Model.IsUrgent)` |
| Render repeated UI | `@foreach (var item in Model.Complaints)` |
| Use layout | `Layout = "_Layout"` |
| Generate MVC links | `asp-controller`, `asp-action` |

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Thinking Razor is a separate programming language | Razor is a markup syntax that uses C# and HTML |
| Writing business logic inside Views | Keep business logic in services/controllers and presentation logic in Views |
| Using ViewBag for every page | Prefer strongly typed ViewModels |
| Hardcoding URLs inside Views | Use Tag Helpers and URL helpers |

---

## Interview Line

**Razor is the ASP.NET Core markup syntax that allows MVC Views to render dynamic HTML using C# expressions, ViewModels, conditions, loops, and Tag Helpers.**

---

# 2. Razor View File Extension

## What

In MVC, Razor View files usually use:

```text
.cshtml
```

The extension means:

```text
C# + HTML
```

---

## Example

```text
Views/Home/Index.cshtml
Views/Complaints/Index.cshtml
Views/Complaints/Create.cshtml
Views/Complaints/Details.cshtml
Views/Shared/_Layout.cshtml
Views/Shared/_ValidationScriptsPartial.cshtml
```

---

## Important Difference

| File Type | Used For |
| --- | --- |
| `.cshtml` | MVC Views and Razor Pages using C# |
| `.razor` | Blazor Razor Components |
| `.html` | Static HTML only |
| `.cs` | C# classes such as controllers, services, models, ViewModels |

---

## Smart Society Example

For a `ComplaintsController`, MVC normally expects Views in:

```text
Views/Complaints
```

Examples:

```text
Views/Complaints/Index.cshtml
Views/Complaints/Create.cshtml
Views/Complaints/Details.cshtml
```

If the controller is named `ComplaintController`, then the folder convention becomes:

```text
Views/Complaint
```

Use the folder name that matches the controller name without the `Controller` suffix.

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Creating `Index.html` for MVC View | Use `Index.cshtml` |
| Putting complaint Views directly under `Views` | Put controller-specific Views under `Views/Complaints` |
| Confusing `.razor` with MVC `.cshtml` | `.razor` is usually for Razor Components/Blazor |
| Naming folder `ComplaintsController` | Folder should normally be `Complaints` |

---

## Interview Line

**In ASP.NET Core MVC, Razor Views are normally `.cshtml` files stored under `Views/[ControllerName]` or `Views/Shared`.**

# 3. Controller To Razor View Flow

## What

A controller action returns a View.

```csharp
public IActionResult Index()
{
    return View();
}
```

MVC then locates the matching Razor View.

---

## Flow

```text
Browser request
↓
Routing selects controller action
↓
Controller prepares data
↓
Controller returns View(model)
↓
MVC finds .cshtml file
↓
Razor renders HTML
↓
HTML response goes to browser
```

---

## Smart Society Example

Request:

```text
GET /Complaints
```

Controller:

```csharp
public class ComplaintsController : Controller
{
    public IActionResult Index()
    {
        return View();
    }
}
```

Expected View:

```text
Views/Complaints/Index.cshtml
```

---

## With Model

```csharp
public IActionResult Details(int id)
{
    var model = new ComplaintDetailsViewModel
    {
        Id = id,
        Title = "Lift not working",
        Status = "Open"
    };

    return View(model);
}
```

View:

```cshtml
@model ComplaintDetailsViewModel

<h1>@Model.Title</h1>
<p>@Model.Status</p>
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Returning `View()` but missing the `.cshtml` file | Create the matching View file |
| Returning model but not declaring `@model` | Add the correct `@model` directive |
| Using wrong View folder | Match the controller name convention |
| Doing database queries directly in View | Query in service/controller, display in View |

---

## Interview Line

**In MVC, the controller handles the request and passes data to a Razor View, while the Razor View renders the final HTML response.**

# 4. View Discovery Convention

## What

View discovery is the MVC process of finding the correct `.cshtml` file for an action.

For this action:

```csharp
public class ComplaintsController : Controller
{
    public IActionResult Details()
    {
        return View();
    }
}
```

MVC normally searches:

```text
Views/Complaints/Details.cshtml
Views/Shared/Details.cshtml
```

---

## Why

View discovery avoids writing the full View path in every action.

Instead of this:

```csharp
return View("~/Views/Complaints/Details.cshtml");
```

We normally write:

```csharp
return View();
```

---

## Smart Society Mapping

| Controller | Action | Expected View |
| --- | --- | --- |
| `ComplaintsController` | `Index` | `Views/Complaints/Index.cshtml` |
| `ComplaintsController` | `Create` | `Views/Complaints/Create.cshtml` |
| `ComplaintsController` | `Details` | `Views/Complaints/Details.cshtml` |
| `DashboardController` | `Index` | `Views/Dashboard/Index.cshtml` |

---

## Explicit View Name

```csharp
return View("ComplaintSummary", model);
```

MVC searches for:

```text
Views/Complaints/ComplaintSummary.cshtml
Views/Shared/ComplaintSummary.cshtml
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Action is `Details` but View file is `Detail.cshtml` | Keep names aligned |
| Controller is plural but folder is singular | Match controller name without `Controller` |
| Returning a View from an API-only controller without MVC View setup | Use MVC template or ensure Views and MVC services exist |
| Using full paths everywhere | Use convention unless there is a strong reason |

---

## Interview Line

**MVC View discovery finds Razor Views using controller and action naming conventions, usually under `Views/[ControllerName]/[ActionName].cshtml`.**

# 5. The @ Symbol

## What

The `@` symbol tells Razor to switch from HTML to C#.

Example:

```cshtml
<p>Today is @DateTime.Now</p>
```

---

## Why

Without `@`, Razor treats text as HTML.

With `@`, Razor evaluates the expression on the server and writes the result into the HTML output.

---

## Smart Society Example

```cshtml
<h2>@Model.PageTitle</h2>
<p>Total complaints: @Model.TotalComplaints</p>
```

---

## Escape @ Symbol

To show an actual `@` symbol, write `@@`.

```cshtml
<p>Support email: support@@smartsociety.local</p>
```

Rendered output:

```text
support@smartsociety.local
```

---

## Email Note

Email addresses inside normal HTML attributes are usually handled safely:

```html
<a href="mailto:support@smartsociety.local">Email Support</a>
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Forgetting `@` before C# expression | Use `@Model.Property` |
| Using too many `@` symbols inside code block | Inside C# code block, normal C# syntax applies |
| Not escaping display-only `@` | Use `@@` when needed |
| Writing complex business expressions in View | Prepare values in ViewModel |

---

## Interview Line

**The `@` symbol is Razor’s transition character from HTML markup to C# code or expressions.**

---

# 6. Implicit Razor Expressions

## What

An implicit expression starts with `@` followed by C# code.

```cshtml
<p>@Model.Title</p>
<p>@DateTime.Now</p>
```

---

## Smart Society Example

```cshtml
<h3>@complaint.Title</h3>
<span>@complaint.Status</span>
```

---

## Good Use Cases

```text
Property values
Simple method calls
Date values
Numbers
Boolean display decisions prepared earlier
```

---

## Example

```cshtml
<p>Complaint Id: @Model.Id</p>
<p>Created On: @Model.CreatedOn.ToString("dd-MMM-yyyy")</p>
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Writing complex generic method calls as implicit expressions | Use explicit expressions `@(...)` |
| Adding spaces in the middle of implicit expression | Use `@(...)` for complex expressions |
| Formatting too much inside the View | Add display-ready properties to ViewModel when possible |
| Accessing null nested properties directly | Use null checks or prepare safe ViewModel values |

---

## Interview Line

**Implicit Razor expressions are short `@` expressions used to render simple C# values inside HTML.**

---

# 7. Explicit Razor Expressions

## What

An explicit expression uses:

```text
@(...)
```

Example:

```cshtml
<p>Next review date: @(DateTime.Today.AddDays(7))</p>
```

---

## Why

Explicit expressions remove confusion when Razor cannot clearly identify where the C# expression ends.

---

## Smart Society Example

```cshtml
<p>Age in days: @((DateTime.Today - Model.CreatedOn.Date).Days)</p>
```

Another example:

```cshtml
<span class="badge">
    @(Model.IsUrgent ? "Urgent" : "Normal")
</span>
```

---

## Concatenation Example

```cshtml
<p>Complaint No: CMP-@(Model.Id)</p>
```

Without explicit expression, the output may not be parsed as expected.

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Using implicit syntax for complex expression | Use `@(...)` |
| Making View unreadable with long expressions | Move logic to ViewModel |
| Using explicit expression for every simple value | Use simple `@Model.Title` when enough |
| Creating side effects inside explicit expression | Keep Views display-focused |

---

## Interview Line

**Explicit Razor expressions use `@(...)` when the C# expression is complex or needs clear boundaries inside HTML.**

---

# 8. Razor Code Blocks

## What

A Razor code block uses:

```cshtml
@{
    var title = "Complaints";
}
```

C# statements inside the block are executed, but they are not directly rendered unless written later.

---

## Example

```cshtml
@{
    ViewData["Title"] = "Complaint List";
    var total = Model.Complaints.Count;
}

<h1>@ViewData["Title"]</h1>
<p>Total: @total</p>
```

---

## Smart Society Example

```cshtml
@{
    var openCount = Model.Complaints.Count(x => x.Status == "Open");
    var resolvedCount = Model.Complaints.Count(x => x.Status == "Resolved");
}

<p>Open: @openCount</p>
<p>Resolved: @resolvedCount</p>
```

---

## Important Rule

Use code blocks for presentation preparation only.

Good in View:

```text
Setting page title
Choosing CSS class
Calculating display count from already-provided model
Preparing small display variables
```

Avoid in View:

```text
Database query
HTTP call
Business decision
Authorization decision
Complex workflow calculation
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Writing service calls in Razor code block | Call services before returning View |
| Adding large business logic in View | Keep logic in service layer |
| Expecting code block variables before declaration | Razor executes in order |
| Mixing too much C# with HTML | Prepare ViewModel cleanly |

---

## Interview Line

**Razor code blocks allow C# statements inside Views, but they should be limited to presentation preparation, not business logic.**

---

# 9. Razor Conditions

## What

Razor supports C# conditional statements.

```cshtml
@if (Model.HasComplaints)
{
    <p>Complaints available.</p>
}
else
{
    <p>No complaints found.</p>
}
```

---

## Smart Society Example

```cshtml
@if (Model.Status == "Open")
{
    <span class="badge bg-warning">Open</span>
}
else if (Model.Status == "Resolved")
{
    <span class="badge bg-success">Resolved</span>
}
else
{
    <span class="badge bg-secondary">@Model.Status</span>
}
```

---

## Switch Example

```cshtml
@switch (Model.Priority)
{
    case "High":
        <span class="badge bg-danger">High</span>
        break;
    case "Medium":
        <span class="badge bg-warning">Medium</span>
        break;
    default:
        <span class="badge bg-secondary">Low</span>
        break;
}
```

---

## Common Use Cases

```text
Empty state UI
Role-based menu display
Status badge rendering
Priority highlight
Show or hide action buttons
Validation summary display
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Using View condition as security | Enforce security in authorization too |
| Repeating long status conditions everywhere | Use a partial, helper, or ViewModel property later |
| Hiding button but leaving action unprotected | Protect controller actions also |
| Complex business branching in View | Move business rules to service/ViewModel |

---

## Interview Line

**Razor conditions are useful for presentation decisions, but they must not replace server-side authorization or business validation.**

---

# 10. Razor Loops

## What

Razor supports C# loops for repeated HTML.

Common loops:

```text
foreach
for
while
do while
```

For Views, `foreach` is most common.

---

## Smart Society Example

```cshtml
@foreach (var complaint in Model.Complaints)
{
    <tr>
        <td>@complaint.ReferenceNumber</td>
        <td>@complaint.Title</td>
        <td>@complaint.Status</td>
        <td>
            <a asp-controller="Complaints"
               asp-action="Details"
               asp-route-id="@complaint.Id">
                View
            </a>
        </td>
    </tr>
}
```

---

## Empty List Handling

```cshtml
@if (!Model.Complaints.Any())
{
    <p>No complaints found.</p>
}
else
{
    foreach (var complaint in Model.Complaints)
    {
        <p>@complaint.Title</p>
    }
}
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Looping over null collection | Initialize collection as empty list |
| Calling database inside loop | Prepare all data before rendering |
| Rendering large data without paging | Add paging/filtering later |
| Hardcoding links inside loop | Use Tag Helpers with route values |

---

## Interview Line

**Razor loops render repeated HTML for collections such as complaint lists, but the collection should already be prepared by the controller or service.**

# 11. Strongly Typed Views

## What

A strongly typed View declares the model type using:

```cshtml
@model ComplaintDetailsViewModel
```

Then the View can access the model using:

```cshtml
@Model
```

---

## Why

Strongly typed Views provide:

```text
Compile-time checking
IntelliSense support
Clear contract between controller and View
Less runtime error risk
Cleaner enterprise code
```

---

## Smart Society Example

```cshtml
@model ComplaintDetailsViewModel

<h1>@Model.Title</h1>
<p>@Model.Description</p>
<p>@Model.Status</p>
```

Controller:

```csharp
public IActionResult Details(int id)
{
    var model = new ComplaintDetailsViewModel
    {
        Id = id,
        Title = "Water leakage",
        Description = "Leakage near parking area",
        Status = "Open"
    };

    return View(model);
}
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Passing `ComplaintDetailsViewModel` but View declares another type | Match controller model and `@model` |
| Using `@model List<T>` but returning single object | Align View type with returned model |
| Using domain entity directly for every View | Prefer ViewModels for screen-specific data |
| Forgetting namespace imports | Add `@using` in `_ViewImports.cshtml` |

---

## Interview Line

**A strongly typed Razor View declares `@model` and receives a specific ViewModel from the controller, improving safety and maintainability.**

# 12. ViewModel-Based Views

## What

A **ViewModel** is a class designed for a specific screen.

It contains only the data needed by that View.

---

## Why

A database/domain model may not match the UI requirement exactly.

A ViewModel can include:

```text
Display fields
Dropdown data
Page title
Status counts
Validation-friendly properties
Formatted values
Permission flags
```

---

## Smart Society Example

```csharp
public class ComplaintIndexViewModel
{
    public string PageTitle { get; set; } = "Complaints";
    public int TotalComplaints { get; set; }
    public int OpenComplaints { get; set; }
    public List<ComplaintSummaryViewModel> Complaints { get; set; } = [];
}
```

---

## Razor Usage

```cshtml
@model ComplaintIndexViewModel

<h1>@Model.PageTitle</h1>
<p>Total: @Model.TotalComplaints</p>
<p>Open: @Model.OpenComplaints</p>
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Passing EF entity directly to every View | Use screen-specific ViewModel |
| Putting database behavior in ViewModel | ViewModel should carry display data, not data access logic |
| Creating one giant ViewModel for all screens | Create focused ViewModels |
| Duplicating status calculations everywhere | Prepare summary values once |

---

## Interview Line

**A ViewModel shapes data specifically for a Razor screen and keeps the View clean, typed, and maintainable.**

---

# 16. ViewData And ViewBag

## What

`ViewData` and `ViewBag` pass weakly typed data from controller to View.

Example:

```csharp
ViewData["Title"] = "Complaints";

```

---

## Razor Usage

```cshtml
<h1>@ViewData["Title"]</h1>

```

---

## Difference

| Feature | ViewData | ViewBag |
| --- | --- | --- |
| Type | Dictionary | Dynamic wrapper around ViewData |
| Access | `ViewData["Title"]` | `ViewBag.Title` |
| Compile-time safety | No | No |
| Good use | Small metadata | Small metadata |

---

## Smart Society Good Usage

Good:

```text
Page title
Small one-time message
Breadcrumb label
```

Avoid:

```text
Full complaint object
Large list
Core page model
Business rules
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Passing all screen data through ViewBag | Use ViewModel |
| Typing wrong ViewData key | Prefer strongly typed properties |

| Mixing same value in ViewModel and ViewBag | Keep one clean source |

---

## Interview Line

**ViewData and ViewBag are useful for small weakly typed values, but strongly typed ViewModels are preferred for main page data.**

# 17. Razor HTML Encoding

## What

Razor automatically HTML-encodes normal string output.

Example:

```cshtml
<p>@Model.Description</p>
```

If description contains:

```html
<script>alert('x')</script>
```

Razor renders it as text, not executable script.

---

## Why

This helps reduce cross-site scripting risk.

User-entered data such as complaint descriptions must not be rendered as trusted HTML by default.

---

## Smart Society Example

Resident enters complaint description:

```text
Water leakage near <main gate>
```

Razor safely displays it as text.

---

## Dangerous Usage

```cshtml
@Html.Raw(Model.Description)
```

Do not use this for user input.

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Using `Html.Raw` to fix display quickly | Avoid Raw for user input |
| Trusting complaint description HTML | Treat all user content as untrusted |
| Encoding manually everywhere | Let Razor encode normal strings |
| Storing script-like text and rendering Raw | Sanitize and validate with a clear business rule if rich text is required |

---

## Interview Line

**Razor automatically HTML-encodes string output, and `Html.Raw` must not be used with unsanitized user input.**

---

# 18. Razor Comments

## What

Razor comments are written as:

```cshtml
@* This is a Razor comment *@
```

They are not sent to the browser.

---

## HTML Comment Difference

HTML comment:

```html
<!-- This is visible in browser source -->
```

Razor comment:

```cshtml
@* This is removed on server *@
```

---

## Smart Society Example

```cshtml
@* Temporary UI note: replace demo badge after status enum is introduced *@
<span>@Model.Status</span>
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Putting secret information in HTML comments | Browser can see HTML comments |
| Using Razor comments for long-term documentation | Keep documentation in Markdown or code comments |
| Commenting broken Razor blocks incorrectly | Use `@* *@` for Razor markup |
| Leaving outdated comments | Clean before commit |

---

## Interview Line

**Razor comments are removed before rendering, while HTML comments can still appear in the browser source.**

# 19. _ViewImports.cshtml

## What

`_ViewImports.cshtml` defines imports and directives shared by Views.

Common content:

```cshtml
@using SmartSociety.Web
@using SmartSociety.Web.ViewModels
@addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers
```

---

## Why

Without `_ViewImports.cshtml`, each View may need repeated `@using` and Tag Helper setup.

---

## Smart Society Example

Create or update:

```text
src/SmartSociety.Web/Views/_ViewImports.cshtml
```

Recommended:

```cshtml
@using SmartSociety.Web
@using SmartSociety.Web.ViewModels
@addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Forgetting `@addTagHelper` | Add MVC Tag Helpers in `_ViewImports.cshtml` |
| Adding imports separately in every View | Use shared imports |

# 21. Razor And Tag Helpers

## What

Tag Helpers allow server-side code to participate in rendering HTML elements.

They look like normal HTML with special `asp-*` attributes.

---

## Anchor Tag Helper Example

```cshtml
<a asp-controller="Complaints"
   asp-action="Details"
   asp-route-id="@Model.Id">
    View Complaint
</a>
```

Rendered output may become:

```html
<a href="/Complaints/Details/5">View Complaint</a>
```

---

## Form Tag Helper Example

```cshtml
<form asp-controller="Complaints" asp-action="Create" method="post">
    <button type="submit">Submit</button>
</form>
```

---

## Why

Tag Helpers are better than hardcoded links because they are connected to MVC routing.

If route configuration changes later, generated links are easier to maintain.

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Hardcoding `href="/Complaints/Details/5"` everywhere | Use Anchor Tag Helper |
| Forgetting `@addTagHelper` | Add it in `_ViewImports.cshtml` |
| Mixing wrong route parameter names | Match action parameter or route name |
| Assuming Tag Helpers are client-side JavaScript | They run server-side while rendering HTML |

---

## Interview Line

**Tag Helpers make Razor Views HTML-friendly while still using MVC routing and model metadata to generate correct HTML.**

# 22. Razor View Design Rules

## What

A Razor View should mainly focus on presentation.

It should answer:

```text
What should be displayed?
How should it be arranged?
Which simple UI condition applies?
Which links/forms should be generated?
```

---

## Razor Should Not Own

```text
Database queries
Business decisions
Authorization enforcement
Workflow state transition rules
Email sending
File upload processing
Payment logic
Complex calculations
```

---

## Smart Society Rule

Good design:

```text
Service prepares complaint data
Controller selects action result
ViewModel carries screen data
Razor renders HTML
Controller/action authorization protects access
```

Bad design:

```text
Razor queries database
Razor decides who can access complaint
Razor changes complaint status
Razor sends email notification
```

---

## Common Mistake

| Mistake | Correction |
| --- | --- |
| Treating Razor as mini-controller | Keep controller/service responsibilities separate |
| Putting status workflow logic in View | Move workflow logic to service/domain layer |
| Hiding UI and assuming security is complete | Enforce authorization at server endpoint |
| Building unreadable Views | Use ViewModels, partials, and clear sections |

---

## Interview Line

**Razor Views should contain presentation logic only; business logic belongs in services, and access control belongs in authorization-protected endpoints.**

```csharp
using Microsoft.AspNetCore.Mvc;
using SmartSociety.Web.ViewModels;

namespace SmartSociety.Web.Controllers;

public class ComplaintsController : Controller
{
    [HttpGet]
    public IActionResult Index(string? status)
    {
        var complaints = GetDemoComplaints();

        if (!string.IsNullOrWhiteSpace(status))
        {
            complaints = complaints
                .Where(x => x.Status.Equals(
                    status,
                    StringComparison.OrdinalIgnoreCase))
                .ToList();
        }

        var model = new ComplaintIndexViewModel
        {
            PageTitle = "Smart Society Complaints",
            SelectedStatus = status,
            Complaints = complaints,
            TotalComplaints = complaints.Count,
            OpenComplaints = complaints.Count(x => x.Status == "Open"),
            ResolvedComplaints = complaints.Count(x => x.Status == "Resolved")
        };

        return View(model);
    }

    [HttpGet]
    public IActionResult Details(int id)
    {
        var complaint = GetDemoComplaints()
            .FirstOrDefault(x => x.Id == id);

        if (complaint is null)
        {
            return NotFound();
        }

        var model = new ComplaintDetailsViewModel
        {
            Id = complaint.Id,
            ReferenceNumber = complaint.ReferenceNumber,
            Title = complaint.Title,
            Description =

            Category = complaint.Category,
            Priority = complaint.Priority,
            Status = complaint.Status,
            CreatedBy = "Resident User",
            CreatedOn = complaint.CreatedOn,
            CanEdit = complaint.Status != "Resolved"
        };

        return View(model);
    }

        return View();
```

# 35. Interview Explanation

The learner should be able to explain:

```text
In ASP.NET Core MVC, Razor Views are .cshtml files that combine HTML with C# using Razor syntax. A controller action prepares data, usually inside a ViewModel, and returns it to the View using return View(model). MVC then locates the matching View using controller and action naming conventions.

Razor uses the @ symbol to transition from HTML to C#. I can use implicit expressions like @Model.Title, explicit expressions like @(Model.Count + 1), code blocks, conditions, loops, and comments. For enterprise MVC pages, I prefer strongly typed Views because @model provides compile-time checking and IntelliSense.

In the Smart Society project, I use Razor Views for complaint list, complaint details, and complaint create pages. The View displays data, generates links through Tag Helpers, and handles simple presentation conditions like status badges. Business rules, database access, workflow decisions, and authorization do not belong in Razor Views. Razor also HTML-encodes strings by default, so I avoid Html.Raw for user-entered complaint descriptions.
```

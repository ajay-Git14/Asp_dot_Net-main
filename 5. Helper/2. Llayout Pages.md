# 2. Layout Pages in ASP.NET Core MVC

## 1. What Are Layout Pages?

A **Layout Page** in ASP.NET Core MVC is a common parent view used to define repeated UI parts of the website.

Examples:

- Header
- Navigation menu
- Sidebar
- Footer
- CSS links
- JavaScript links
- Common page container
- Common company branding

Instead of writing the same header, footer, and menu in every `.cshtml` view, we create one layout file and all views use it.

The most common layout file is:

```text
Views/Shared/_Layout.cshtml
```

In ASP.NET Core MVC, layout files help keep the UI consistent and reduce duplicate code across views.

---

## 2. Why Do We Need Layout Pages?

Without a layout page, every view needs repeated HTML.

Example problem:

```text
Home Page     -> Header + Menu + Footer
About Page    -> Header + Menu + Footer
Contact Page  -> Header + Menu + Footer
Product Page  -> Header + Menu + Footer
```

If the company logo changes, we must update every page manually.

With layout page:

```text
_Layout.cshtml -> Header + Menu + Footer
Home.cshtml    -> Only page-specific content
About.cshtml   -> Only page-specific content
Contact.cshtml -> Only page-specific content
```

So layout pages provide:

- Consistent design
- Less duplicate code
- Easier maintenance
- Faster UI changes
- Better enterprise-level structure
- Cleaner view files

---

## 3. Real-Life Example

Think of a layout page like a **template notebook page**.

Every notebook page has:

- Same margin
- Same header
- Same footer
- Same page number style

Only the middle content changes.

In MVC:

```text
_Layout.cshtml  -> Fixed notebook format
Index.cshtml    -> Middle content
About.cshtml    -> Middle content
Login.cshtml    -> Middle content
```

## 4. Layout Page Request Flow

When the browser requests a page:

```text
Browser Request
      ↓
Controller Action
      ↓
View File (.cshtml)
      ↓
_ViewStart.cshtml decides layout
      ↓
_Layout.cshtml loads
      ↓
@RenderBody() places view content inside layout
      ↓
Final HTML response goes to browser
```

Example:

```text
/Home/Index
      ↓
HomeController -> Index()
      ↓
Views/Home/Index.cshtml
      ↓
Views/_ViewStart.cshtml
      ↓
Views/Shared/_Layout.cshtml
      ↓
Final page output
```

## 5. Important Layout Files

### 5.1 `_Layout.cshtml`

Main shared layout file.

Common location:

```text
Views/Shared/_Layout.cshtml
```

Purpose:

- Defines common HTML structure
- Loads CSS and JavaScript
- Contains header, menu, footer
- Uses `@RenderBody()` to display child view content
- Uses `@RenderSection()` or `@await RenderSectionAsync()` for optional page-specific scripts

---

### 5.2 `_ViewStart.cshtml`

This file runs before each full view.

Common location:

```text
Views/_ViewStart.cshtml
```

Purpose:

- Sets default layout for all views
- Avoids writing layout setting in every view

Example:

```cshtml
@{
    Layout = "_Layout";
}
```

This means every view will use:

```text
Views/Shared/_Layout.cshtml
```

---

### 5.3 `_ViewImports.cshtml`

This file imports common namespaces and tag helpers for Razor views.

Common location:

```text
Views/_ViewImports.cshtml
```

Example:

```cshtml
@using ExpertSearch.Web
@using ExpertSearch.Web.Models
@addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers
```

Purpose:

- Makes tag helpers available
- Avoids repeating namespace imports
- Supports clean Razor views

---

## 6. Core Layout Keywords

### 6.1 `@RenderBody()`

`@RenderBody()` is the placeholder where the current view content is injected.

Example layout:

```cshtml
<body>
    <header>
        <h1>Expert Search</h1>
    </header>

    <main>
        @RenderBody()
    </main>

    <footer>
        <p>Copyright 2026</p>
    </footer>
</body>
```

If `Index.cshtml` contains:

```cshtml
<h2>Welcome to Expert Search</h2>
<p>This is the home page.</p>
```

Then final output becomes:

```html
<body>
    <header>
        <h1>Expert Search</h1>
    </header>

    <main>
        <h2>Welcome to Expert Search</h2>
        <p>This is the home page.</p>
    </main>

    <footer>
        <p>Copyright 2026</p>
    </footer>
</body>
```

---

### 6.2 `@await RenderSectionAsync()`

Sections are used when a view wants to inject special content into a specific layout area.

Most common use:

- Page-specific JavaScript
- Page-specific CSS
- Page-specific toolbar

Example in `_Layout.cshtml`:

```cshtml
@await RenderSectionAsync("Scripts", required: false)
```

Example in `Index.cshtml`:

```cshtml
@section Scripts {
    <script>
        console.log("Home page script loaded");
    </script>
}
```

Here, the `Scripts` section from the view is rendered at the bottom of the layout page.

---

### 6.3 `required: false`

This means the section is optional.

```cshtml
@await RenderSectionAsync("Scripts", required: false)
```

If the view does not provide a `Scripts` section, no error occurs.

---

### 6.4 `required: true`

This means every view using this layout must define that section.

```cshtml
@await RenderSectionAsync("PageHeader", required: true)
```

If a view does not define `PageHeader`, ASP.NET Core throws an error.

Use required sections carefully.

## 14. Important Rule About Sections and Partials

Sections are available only to the immediate layout page.

This means:

```text
View -> Layout     ✅ section works
Partial -> Layout  ❌ section should not be defined inside partial
```

Do not write this inside a partial view:

```cshtml
@section Scripts {
    <script>alert("Wrong place");</script>
}
```

Write the section in the main view instead.

## 15. Common Mistakes and Fixes

### Mistake 1: Missing `@RenderBody()`

Problem:

```text
RenderBody has not been called for the page.
```

Fix:

```cshtml
<main>
    @RenderBody()
</main>
```

Every layout must render the body or explicitly ignore it.

---

### Mistake 2: Required Section Not Found

Problem:

```text
Section not defined: Scripts
```

Reason:

```cshtml
@await RenderSectionAsync("Scripts", required: true)
```

But the view does not have:

```cshtml
@section Scripts {
}
```

Fix option 1:

```cshtml
@await RenderSectionAsync("Scripts", required: false)
```

Fix option 2:

Add this in every view:

```cshtml
@section Scripts {
    <script></script>
}
```

---

### Mistake 3: Section Defined But Not Rendered

Problem:

```text
The following sections have been defined but have not been rendered.
```

Reason:

View has:

```cshtml
@section Scripts {
    <script></script>
}
```

But layout does not have:

```cshtml
@await RenderSectionAsync("Scripts", required: false)
```

Fix:

Add section rendering in layout.

---

### Mistake 4: `_ViewStart.cshtml` Placed in Wrong Folder

Wrong:

```text
Views/Shared/_ViewStart.cshtml
```

Correct:

```text
Views/_ViewStart.cshtml
```

---

### Mistake 5: Tag Helpers Not Working

Problem:

```cshtml
<a asp-controller="Home" asp-action="Index">Home</a>
```

renders as plain attributes.

Reason:

`_ViewImports.cshtml` is missing tag helper import.

Fix:

```cshtml
@addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers
```

## 16. Enterprise Best Practices

### 16.1 Keep Layout Clean

Do not put heavy business logic inside layout.

Bad:

```cshtml
@{
    var users = database.Users.ToList();
}
```

Good:

- Use controller
- Use service
- Use view model
- Use view component for dynamic layout data

---

### 16.2 Use Partial Views for Repeated UI

Use partials for:

- Navbar
- Footer
- Sidebar
- Alert messages
- Breadcrumb
- User profile menu

---

### 16.3 Use Sections for Page-Specific Scripts

Do not load every page script globally.

Good:

```cshtml
@section Scripts {
    <script src="~/js/home.js" asp-append-version="true"></script>
}
```

---

### 16.4 Use `ViewData["Title"]`

In each view:

```cshtml
@{
    ViewData["Title"] = "Home";
}
```

In layout:

```cshtml
<title>@ViewData["Title"] - Expert Search</title>
```

This improves browser tab titles and SEO basics.

---

### 16.5 Use Different Layouts for Different Areas

Example:

```text
Public Layout  -> Website pages
Admin Layout   -> Admin panel pages
Auth Layout    -> Login/Register pages
Print Layout   -> Printable pages
```

# Subjective Questions

## Q1. What is a layout page in ASP.NET Core MVC?

A layout page is a shared Razor view used to define common UI structure for multiple views, such as header, navigation, footer, styles, and scripts.

---

## Q2. Why do we use `_Layout.cshtml`?

We use `_Layout.cshtml` to avoid duplicate HTML in every view and to maintain consistent UI across the application.

---

## Q3. What is the role of `@RenderBody()`?

`@RenderBody()` marks the place in layout where the child view content will be rendered.

---

## Q4. What is the role of `_ViewStart.cshtml`?

`_ViewStart.cshtml` runs before full views and usually sets the default layout for all views.

---

## Q5. What is the role of `_ViewImports.cshtml`?

`_ViewImports.cshtml` imports common namespaces and tag helpers for Razor views.

---

## Q6. What is a section in Razor layout?

A section is a named content block that a view can provide to a layout. It is commonly used for page-specific scripts or styles.

---

## Q7. What is the difference between required and optional sections?

A required section must be defined by every view using the layout. An optional section may or may not be defined.

---

## Q8. Why should we use partial views in layout?

Partial views help split large layout files into smaller reusable UI files such as navbar, footer, and sidebar.

---

## Q9. How do we create multiple layouts?

We create multiple layout files inside `Views/Shared`, such as `_Layout.cshtml`, `_AdminLayout.cshtml`, and `_AuthLayout.cshtml`, then set the required layout in the view using `Layout = "_AdminLayout";`.

---

## Q10. How do we remove layout from a specific view?

We set `Layout = null;` at the top of the view.

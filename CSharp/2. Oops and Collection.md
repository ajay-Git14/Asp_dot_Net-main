# 4. Topic 1: Class and Object

## What

A **class** is a blueprint.
An **object** is a real instance created from that blueprint.

## Why

Classes help us represent real-world entities in code.

## When

Use classes when your application needs to represent structured data or behavior.

Examples:

* Employee
* Product
* Customer
* Order
* Invoice
* User

## How

```csharp
public class Employee
{
    public int Id;
    public string Name;
    public string Department;
}
```

Creating an object:

```csharp
Employee employee = new Employee();

employee.Id = 1;
employee.Name = "Amit Sharma";
employee.Department = "IT";
```

## Real-Life Mapping

```text
Employee class = Blank employee form
Employee object = Filled employee form for Amit Sharma
```

## ASP.NET Core Use

In ASP.NET Core, classes are used as:

* Models
* ViewModels
* DTOs
* Services
* Controllers
* Entity Framework entities

# 5. Topic 2: Properties

## What

Properties are controlled fields used to store and expose data in a class.

## Why

Properties are preferred over public fields because they provide better control, readability, and compatibility with frameworks.

## How

```csharp
public class Employee
{
    public int Id { get; set; }

    public string Name { get; set; } = "";

    public string Department { get; set; } = "";

    public decimal Salary { get; set; }
}
```

## ASP.NET Core Importance

ASP.NET Core model binding, validation, Entity Framework Core, and Razor Views commonly work with properties.

Example:

```csharp
public string Name { get; set; } = "";
```

This is better than:

```csharp
public string Name;
```

## Interview Point

In C#, properties provide a clean way to expose class data while allowing future validation or logic inside getters and setters.

# 6. Topic 3: Constructor

## What

A constructor is a special method that runs automatically when an object is created.

## Why

It is used to initialize object data.

## How

```csharp
public class Employee
{
    public int Id { get; set; }
    public string Name { get; set; } = "";

    public Employee()
    {
        Console.WriteLine("Employee object created");
    }
}
```

## Parameterized Constructor

```csharp
public class Employee
{
    public int Id { get; set; }
    public string Name { get; set; } = "";

    public Employee(int id, string name)
    {
        Id = id;
        Name = name;
    }
}
```

Using it:

```csharp
Employee employee = new Employee(1, "Amit Sharma");
```

## ASP.NET Core Connection

Constructors are heavily used in **Dependency Injection**.

Example:

```csharp
public class EmployeeController : Controller
{
    private readonly IEmployeeService _employeeService;

    public EmployeeController(IEmployeeService employeeService)
    {
        _employeeService = employeeService;
    }
}
```

Here ASP.NET Core automatically provides `IEmployeeService` through constructor injection.

# 7. Topic 4: Encapsulation

## What

Encapsulation means keeping data and behavior together and controlling direct access to data.

## Why

It protects internal data from unwanted changes.

## How

```csharp
public class BankAccount
{
    private decimal balance;

    public void Deposit(decimal amount)
    {
        if (amount <= 0)
        {
            Console.WriteLine("Invalid amount");
            return;
        }

        balance += amount;
    }

    public decimal GetBalance()
    {
        return balance;
    }
}
```

Using it:

```csharp
BankAccount account = new BankAccount();

account.Deposit(5000);

Console.WriteLine(account.GetBalance());
```

## Real-Life Example

A bank customer cannot directly change account balance.
They must use approved operations like deposit or withdrawal.

## ASP.NET Core Connection

In service classes, business rules should be protected inside methods.

Example:

```csharp
employeeService.ApproveLeave(employeeId);
```

Instead of directly changing database values everywhere.

# 8. Topic 5: Access Modifiers

## What

Access modifiers control where a class member can be accessed.

## Common Access Modifiers

| Modifier  | Meaning                                   |
| --------- | ----------------------------------------- |
| public    | Accessible from anywhere                  |
| private   | Accessible only inside the same class     |
| protected | Accessible inside class and child classes |
| internal  | Accessible within same project/assembly   |

## Example

```csharp
public class Employee
{
    public string Name { get; set; } = "";

    private decimal salary;

    public void SetSalary(decimal amount)
    {
        if (amount > 0)
        {
            salary = amount;
        }
    }
}
```

## ASP.NET Core Use

Access modifiers help keep controllers, services, and models clean and safe.

# 9. Topic 6: Inheritance

## What

Inheritance allows one class to reuse properties and methods from another class.

## Why

It avoids duplicate code.

## How

```csharp
public class Person
{
    public string Name { get; set; } = "";
    public string Email { get; set; } = "";
}

public class Employee : Person
{
    public string Department { get; set; } = "";
}
```

Using it:

```csharp
Employee employee = new Employee();

employee.Name = "Priya Verma";
employee.Email = "priya@example.com";
employee.Department = "HR";
```

## Real-Life Mapping

```text
Person = Common identity
Employee = Person with department details
Customer = Person with purchase details
```

## ASP.NET Core Connection

Inheritance is useful, but in ASP.NET Core we often prefer **interfaces and composition** over deep inheritance.

# 10. Topic 7: Polymorphism

## What

Polymorphism means one method name or contract can behave differently based on implementation.

## Example Using Virtual and Override

```csharp
public class Notification
{
    public virtual void Send()
    {
        Console.WriteLine("Sending notification");
    }
}

public class EmailNotification : Notification
{
    public override void Send()
    {
        Console.WriteLine("Sending email notification");
    }
}

public class SmsNotification : Notification
{
    public override void Send()
    {
        Console.WriteLine("Sending SMS notification");
    }
}
```

Using it:

```csharp
Notification notification = new EmailNotification();
notification.Send();
```

## ASP.NET Core Connection

Polymorphism helps when different implementations follow the same contract.

Example:

```text
IPaymentService
    ↓
CreditCardPaymentService
UPIPaymentService
NetBankingPaymentService
```

# 11. Topic 8: Interface

## What

An interface is a contract.
It defines what a class must do, but not how it should do it.

## Why

Interfaces help create loosely coupled and testable code.

## How

```csharp
public interface IEmployeeService
{
    void AddEmployee(Employee employee);

    List<Employee> GetEmployees();
}
```

Implementation:

```csharp
public class EmployeeService : IEmployeeService
{
    private readonly List<Employee> employees = new List<Employee>();

    public void AddEmployee(Employee employee)
    {
        employees.Add(employee);
    }

    public List<Employee> GetEmployees()
    {
        return employees;
    }
}
```

Using it:

```csharp
IEmployeeService employeeService = new EmployeeService();

employeeService.AddEmployee(new Employee
{
    Id = 1,
    Name = "Amit Sharma",
    Department = "IT",
    Salary = 60000
});
```

## ASP.NET Core Connection

Interfaces are very important in ASP.NET Core because they are used with Dependency Injection.

```csharp
builder.Services.AddScoped<IEmployeeService, EmployeeService>();
```

## Interview Point

Interfaces help achieve abstraction, loose coupling, dependency injection, and testability.

# 12. Topic 9: Collections

## What

Collections are used to store multiple values or objects.

## Why

Real applications rarely work with one record. They work with lists of records.

Examples:

* List of employees
* List of products
* List of orders
* List of users

---

## Array

```csharp
string[] departments = { "IT", "HR", "Finance" };

foreach (string department in departments)
{
    Console.WriteLine(department);
}
```

## Limitation

Array size is fixed.

---

## List

```csharp
List<string> departments = new List<string>();

departments.Add("IT");
departments.Add("HR");
departments.Add("Finance");

foreach (string department in departments)
{
    Console.WriteLine(department);
}
```

## Why List Is Common

`List<T>` is flexible and commonly used in ASP.NET Core applications.

---

## List of Objects

```csharp
List<Employee> employees = new List<Employee>
{
    new Employee { Id = 1, Name = "Amit Sharma", Department = "IT", Salary = 60000 },
    new Employee { Id = 2, Name = "Priya Verma", Department = "HR", Salary = 55000 },
    new Employee { Id = 3, Name = "Rahul Mehta", Department = "Finance", Salary = 70000 }
};

foreach (Employee employee in employees)
{
    Console.WriteLine($"{employee.Id} - {employee.Name} - {employee.Department}");
}
```

## ASP.NET Core Connection

A controller often sends a list of objects to a view.

```csharp
public IActionResult List()
{
    List<Employee> employees = employeeService.GetEmployees();

    return View(employees);
}
```

---

## Dictionary

## What

Dictionary stores data in key-value format.

## Example

```csharp
Dictionary<int, string> departments = new Dictionary<int, string>();

departments.Add(1, "IT");
departments.Add(2, "HR");
departments.Add(3, "Finance");

Console.WriteLine(departments[1]);
```

## Real-Life Example

```text
DepartmentId → DepartmentName
1            → IT
2            → HR
3            → Finance
```

## ASP.NET Core Use

Dictionaries are useful for:

* Configuration-style data
* Lookup values
* Mapping IDs to names
* Fast key-based access

# 13. Complete Hour 2 Practice Code

```csharp
using System;
using System.Collections.Generic;

public class Employee
{
    public int Id { get; set; }

    public string Name { get; set; } = "";

    public string Department { get; set; } = "";

    public decimal Salary { get; set; }
}

public interface IEmployeeService
{
    void AddEmployee(Employee employee);

    List<Employee> GetEmployees();
}

public class EmployeeService : IEmployeeService
{
    private readonly List<Employee> employees = new List<Employee>();

    public void AddEmployee(Employee employee)
    {
        employees.Add(employee);
    }

    public List<Employee> GetEmployees()
    {
        return employees;
    }
}

public class Program
{
    public static void Main()
    {
        IEmployeeService employeeService = new EmployeeService();

        employeeService.AddEmployee(new Employee
        {
            Id = 1,
            Name = "Amit Sharma",
            Department = "IT",
            Salary = 60000
        });

        employeeService.AddEmployee(new Employee
        {
            Id = 2,
            Name = "Priya Verma",
            Department = "HR",
            Salary = 55000
        });

        employeeService.AddEmployee(new Employee
        {
            Id = 3,
            Name = "Rahul Mehta",
            Department = "Finance",
            Salary = 70000
        });

        List<Employee> employees = employeeService.GetEmployees();

        foreach (Employee employee in employees)
        {
            Console.WriteLine($"{employee.Id} - {employee.Name} - {employee.Department} - {employee.Salary}");
        }
    }
}
```

# 15. Common Mistakes

## Mistake 1: Confusing Class and Object

Wrong understanding:

```text
Class and object are same.
```

Correct understanding:

```text
Class is blueprint.
Object is actual instance.
```

## Mistake 2: Using Public Fields Instead of Properties

Avoid:

```csharp
public string Name;
```

Prefer:

```csharp
public string Name { get; set; } = "";
```

## Mistake 3: Putting Everything in Main Method

Avoid writing all logic inside `Main`.

Create classes and services.

## Mistake 4: Not Understanding Interface Purpose

Interface is not for direct object data.
It defines behavior contract.

## Mistake 5: Overusing Inheritance

Do not create deep inheritance chains unnecessarily.

Prefer simple classes and interfaces.

## Mistake 6: Forgetting Generic Type in List

Wrong:

```csharp
List employees = new List();
```

Correct:

```csharp
List<Employee> employees = new List<Employee>();
```

# 16. Interview Questions for Hour 2

## Q1. What is a class in C#?

A class is a blueprint used to define data and behavior for objects.

## Q2. What is an object?

An object is an instance of a class.

## Q3. What is a property?

A property is a class member used to expose data using get and set accessors.

## Q4. What is a constructor?

A constructor is a special method that runs automatically when an object is created.

## Q5. What is encapsulation?

Encapsulation means hiding internal data and exposing controlled behavior through methods or properties.

## Q6. What is inheritance?

Inheritance allows one class to reuse members of another class.

## Q7. What is polymorphism?

Polymorphism allows the same method or contract to have different implementations.

## Q8. What is an interface?

An interface is a contract that defines methods or properties a class must implement.

## Q9. Why are interfaces important in ASP.NET Core?

Interfaces are important for dependency injection, loose coupling, service abstraction, and unit testing.

## Q10. What is `List<T>`?

`List<T>` is a generic collection used to store multiple items of the same type.

## Q11. What is the difference between Array and List?

Array has a fixed size.
List is dynamic and can grow or shrink.

## Q12. What is Dictionary?

Dictionary is a collection that stores data in key-value pairs.

# 2. Program.cs

## What

`Program.cs` is the entry point of an ASP.NET Core application.

It is the file where the application is configured and started.

In modern ASP.NET Core, `Program.cs` usually contains:

```text
Service registration
Middleware pipeline configuration
Routing configuration
Application startup
```

## Why

Every ASP.NET Core application needs a starting point.

`Program.cs` tells the application:

```text
Which services are available
Which middleware should run
How routing should work
How the app should start
```

## Typical Program.cs Example

```csharp
var builder = WebApplication.CreateBuilder(args);

// Add services to the container.
builder.Services.AddControllersWithViews();

var app = builder.Build();

// Configure the HTTP request pipeline.
if (!app.Environment.IsDevelopment())
{
    app.UseExceptionHandler("/Home/Error");
    app.UseHsts();
}

app.UseHttpsRedirection();
app.UseStaticFiles();

app.UseRouting();

app.UseAuthorization();

app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");

app.Run();
```

---

## Step-By-Step Explanation

| Code                                         | Meaning                              |
| -------------------------------------------- | ------------------------------------ |
| `WebApplication.CreateBuilder(args)`         | Creates the application builder      |
| `builder.Services.AddControllersWithViews()` | Adds MVC controller and view support |
| `builder.Build()`                            | Builds the application               |
| `app.UseHttpsRedirection()`                  | Redirects HTTP requests to HTTPS     |
| `app.UseStaticFiles()`                       | Enables serving CSS, JS, images      |
| `app.UseRouting()`                           | Enables route matching               |
| `app.UseAuthorization()`                     | Enables authorization checks         |
| `MapControllerRoute()`                       | Defines default MVC route            |
| `app.Run()`                                  | Starts the application               |

---

## Smart Society Mapping

Later, `Program.cs` will configure many project-level things:

```text
MVC support
Dependency Injection
EF Core DbContext

Authentication
Authorization

```

Example future configuration:

```csharp

```

This means:

```text

```

---

## Common Mistake

| Mistake                                      | Correction                                         |
| -------------------------------------------- | -------------------------------------------------- |
| Ignoring Program.cs                          | Program.cs is the startup and configuration center |
| Changing middleware order randomly           | Middleware order matters                           |
| Removing `UseRouting()` accidentally         | Routing will not work properly                     |
| Removing `MapControllerRoute()`              | MVC controller routes may stop working             |
| Registering services after `builder.Build()` | Register services before building the app          |

# 3. appsettings.json

## What

`appsettings.json` is the configuration file of an ASP.NET Core application.

It stores application settings such as:

```text
Connection strings
Logging settings
Application-specific configuration
External service settings
Environment-based values
```

Example:

```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "AllowedHosts": "*"
}
```

## Why

Hardcoding settings inside code is a bad practice.

For example, this is not good:

```csharp
var connectionString = "Server=.;Database=SmartSocietyDb;Trusted_Connection=True;";
```

Better approach:

```text
Store configuration in appsettings.json
Read it through configuration system
Change settings without changing code
```

## Future Smart Society appsettings.json

Later, we may add:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=(localdb)\\MSSQLLocalDB;Database=SmartSocietyDb;Trusted_Connection=True;"
  },
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "AllowedHosts": "*"
}
```

## Smart Society Mapping

`appsettings.json` will store:

```text
Database connection string
Logging level
File upload settings
Email configuration later if needed
Environment-specific settings
```

## Common Mistake

| Mistake                                                                      | Correction                                                     |
| ---------------------------------------------------------------------------- | -------------------------------------------------------------- |
| Hardcoding connection string in controller                                   | Store it in appsettings.json                                   |
| Committing real passwords/secrets                                            | Use environment variables or secret manager for sensitive data |
| Editing only appsettings.Development.json and expecting production to change | Understand environment-specific files                          |
| Not understanding Logging section                                            | Logging section controls how much information is recorded      |

## Interview Line

**appsettings.json stores application configuration such as connection strings, logging settings, and environment-specific values, helping keep configuration separate from code.**

# 10. Understanding ASP.NET Core Request Lifecycle

## What

The **request lifecycle** explains what happens when a user sends a request to an ASP.NET Core application.

Example:

```text
User opens /Home/Index
```

ASP.NET Core receives the request, processes it, selects the controller/action, renders the view, and returns a response.

## Why

Request lifecycle understanding is essential for debugging and development.

It helps learners understand:

```text
Why a controller action is called
Why a view is rendered
Why routing fails
Why middleware order matters
Why authorization may block a request
Why static files work separately
```

## High-Level Request Lifecycle

```text
Browser sends request
↓
Request enters ASP.NET Core application
↓
Middleware pipeline starts
↓
Routing identifies endpoint
↓
Controller is selected
↓
Action method executes
↓
Model/service/database logic may run
↓
View is rendered
↓
Response returns to browser
```

# 12. Middleware Pipeline

## What

Middleware is a component that processes requests and responses.

ASP.NET Core uses a middleware pipeline.

Each middleware can:

```text
Process the request
Pass request to next middleware
Stop the request
Modify the response
```

Common middleware:

```text
Exception handling middleware
HTTPS redirection middleware
Static files middleware
Routing middleware
Authentication middleware
Authorization middleware
```

## Example In Program.cs

```csharp
app.UseHttpsRedirection();
app.UseStaticFiles();

app.UseRouting();

app.UseAuthorization();
```

## Why Middleware Order Matters

The order is important.

Example:

```text
UseRouting should come before UseAuthorization
UseStaticFiles should come before routing for static file serving
Authentication should come before Authorization when authentication is configured
```

## Smart Society Mapping

In the Smart Society project, middleware will handle:

```text
HTTPS redirection
Serving CSS/JS files
Routing requests
Authentication
Authorization
Error handling
```

## Common Mistake

| Mistake                                        | Correction                                  |
| ---------------------------------------------- | ------------------------------------------- |
| Changing middleware order randomly             | Middleware order matters                    |
| Missing `UseStaticFiles()`                     | CSS/JS may not load                         |
| Using authorization before routing incorrectly | Follow correct middleware order             |
| Thinking middleware is same as controller      | Middleware runs before controller selection |

## Interview Line

**Middleware is part of the ASP.NET Core request pipeline and processes requests before they reach the controller and responses before they return to the browser.**

# 13. Routing

## What

Routing maps a URL to a controller action.

Default MVC route:

```csharp
app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");
```

## Meaning

```text
{controller=Home} → Default controller is Home
{action=Index} → Default action is Index
{id?} → Optional id parameter
```

## Examples

| URL                     | Controller                                                   | Action  | Id   |
| ----------------------- | ------------------------------------------------------------ | ------- | ---- |
| `/`                     | HomeController                                               | Index   | None |
| `/Home/Index`           | HomeController                                               | Index   | None |
| `/Complaints/Create`    | ComplaintsController or ComplaintController depending naming | Create  | None |
| `/Complaints/Details/5` | ComplaintsController or ComplaintController                  | Details | 5    |

## Naming Note For Our Project

We will use:

```text
ComplaintController
```

So route will commonly be:

```text
/Complaint/Create
```

But if we want URL as:

```text
/Complaints/Create
```

we can later use routing customization or name the controller:

```text
ComplaintsController
```

For clarity and REST-style naming, many teams prefer plural controller names for resources:

```text
ComplaintsController
```

For beginner clarity, either can work, but we will keep naming consistent once selected.

## Recommended For This Project

Use:

```text
ComplaintsController
```

because URL naturally becomes:

```text
/Complaints/Create
/Complaints/Details/5
```

## Smart Society Mapping

| URL                     | Controller           | Action  |
| ----------------------- | -------------------- | ------- |
| `/Home/Index`           | HomeController       | Index   |

```csharp
        return View();
    }
}
```

Future version:

```csharp
public async Task<IActionResult> Details(int id)
{
    var complaint = await _complaintService.GetComplaintByIdAsync(id);

    if (complaint == null)
    {
        return NotFound();
    }

    return View(complaint);
}
```

# 27. Short Answers

1. Project layout is the folder and file structure of an ASP.NET Core MVC project.
2. Program.cs configures services, middleware, routing, and starts the application.
3. appsettings.json stores application configuration such as logging and connection strings.
4. Controllers folder stores controller classes that handle requests.
5. Models folder stores classes that represent application data or business objects.
6. Views folder stores Razor `.cshtml` files that render UI.
7. wwwroot stores static files such as CSS, JavaScript, images, and client libraries.
8. launchSettings.json controls local launch profiles, ports, URLs, and environment variables.
9. Dependencies are external libraries, framework references, and packages used by the project.
10. Middleware is a request-processing component in the ASP.NET Core pipeline.
11. Middleware order matters because each middleware runs in sequence and can affect later processing.
12. Routing maps incoming URLs to controller actions or endpoints.
13. `/Home/Index` maps to `HomeController` and `Index` action.
14. `/Complaints/Details/5` maps to `ComplaintsController`, `Details` action, and `id = 5`.
15. ASP.NET Core finds the matching Razor view, renders HTML, and returns it to the browser.

```text
In ASP.NET Core MVC, Program.cs is the entry point where services, middleware, and routing are configured. appsettings.json stores application configuration such as logging and connection strings. Controllers handle requests, Models represent application data, Views render UI, and wwwroot stores static files.

When a browser requests /Complaints/Details/5, the request enters the ASP.NET Core application and passes through the middleware pipeline.
```

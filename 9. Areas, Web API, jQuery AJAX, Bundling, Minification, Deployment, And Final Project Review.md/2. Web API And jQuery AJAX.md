# 1. Why This Topic Is Important

## What

Until now, our Smart Society Issue Management System has used traditional ASP.NET Core MVC flow:

```text
Browser request
↓
MVC Controller
↓
Service
↓
Repository
↓
Database
↓
Controller returns View
↓
Full page reload
```

This is good for normal page-based applications.

But modern web applications often need interactive behavior without reloading the full page.

Examples:

```text
Admin updates complaint status without full page reload
Dashboard count refreshes dynamically
Complaint list filters dynamically
Staff updates progress from same screen
Resident sees latest status without refreshing entire page
```

This is where **Web API** and **AJAX** are useful.

---

## Why

Web API allows the server to return data, usually as JSON, instead of returning a full Razor view.

jQuery AJAX allows the browser to call the API in the background.

This helps create:

```text
Interactive UI
Partial updates
Faster user experience
Cleaner frontend/backend communication
API-ready architecture
Future React/Angular/mobile integration foundation
```

---

## Smart Society Mapping

Create APIs:

```text

```

Use AJAX for:

```text
Complaint status update
```


# 2. Introduction To Web API

## What

A **Web API** is an endpoint that allows clients to communicate with the server using HTTP.

Instead of returning HTML views, Web API usually returns data.

Most commonly:

```text
JSON
```

Example API response:

```json
{
  "complaintId": 10,
  "title": "Lift not working",
  "status": "Assigned",
  "priority": "High"
}
```

---

## Why

Web API is useful when the client needs data, not a full page.

Clients can be:

```text
jQuery AJAX
React application
Angular application
Mobile app
Postman
External system
Dashboard widget
```

---

## Smart Society API Use Cases

```text
Get complaint list as JSON
Get complaint details as JSON
Create complaint from API
Update complaint status from AJAX
Refresh dashboard summary dynamically
Filter complaints without full reload
```

---

## API Route Examples

```text
GET /api/complaints
GET /api/complaints/5
POST /api/complaints
PUT /api/complaints/5/status
GET /api/dashboard/summary
```

---

## Simple API Controller Example

```csharp
using Microsoft.AspNetCore.Mvc;

namespace SmartSociety.Web.Controllers.Api
{
    [Route("api/complaints")]
    [ApiController]
    public class ComplaintsApiController : ControllerBase
    {
        [HttpGet]
        public IActionResult GetComplaints()
        {
            var complaints = new[]
            {
                new { ComplaintId = 1, Title = "Lift not working", Status = "New" },
                new { ComplaintId = 2, Title = "Water leakage", Status = "Assigned" }
            };

            return Ok(complaints);
        }
    }
}
```

---

## Output

Request:

```text
GET /api/complaints
```

Response:

```json
[
  {
    "complaintId": 1,
    "title": "Lift not working",
    "status": "New"
  },
  {
    "complaintId": 2,
    "title": "Water leakage",
    "status": "Assigned"
  }
]
```

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Returning View from API controller | Return JSON using Ok, NotFound, BadRequest |
| Mixing API and MVC responsibilities carelessly | Keep API endpoints focused on data |
| Exposing entity directly in every API | Use DTOs |
| Not securing API endpoints | Use Authorize |
| Not testing API separately | Use Postman and browser Network tab |

---

## Interview Line

**A Web API exposes HTTP endpoints that return data, usually JSON, so clients like AJAX, mobile apps, or frontend frameworks can communicate with the server.**

# 3. MVC Controller Vs API Controller

## What

MVC controllers and API controllers both handle HTTP requests, but they serve different purposes.

---

## MVC Controller

MVC controller usually returns:

```text
View
Redirect
Partial View
HTML response
```

Example:

```csharp
public IActionResult Index()
{
    return View();
}
```

---

## API Controller

API controller usually returns:

```text
JSON data
HTTP status codes
DTO objects
```

Example:

```csharp
[HttpGet]
public IActionResult GetComplaints()
{
    return Ok(data);
}
```

---

## Comparison

| Area | MVC Controller | API Controller |
|---|---|---|
| Main Purpose | Render pages | Return data |
| Base Class | `Controller` | `ControllerBase` |
| Common Return | `View()` | `Ok()`, `NotFound()`, `BadRequest()` |
| Output | HTML | JSON |
| Used By | Browser full-page request | AJAX, mobile, frontend apps |
| Smart Society Example | Complaint Create page | Complaint status update API |

---

## Smart Society Example

MVC route:

```text
/Resident/MyComplaints
```

returns a page.

API route:

```text
/api/complaints
```

returns complaint data.

---

## MVC Controller Example

```csharp
public class MyComplaintsController : Controller
{
    public async Task<IActionResult> Index()
    {
        var complaints = await _complaintService.GetComplaintsForResidentAsync(userId);

        return View(complaints);
    }
}
```

---

## API Controller Example

```csharp
[Route("api/complaints")]
[ApiController]
public class ComplaintsApiController : ControllerBase
{
    [HttpGet]
    public async Task<IActionResult> GetComplaints()
    {
        var complaints = await _complaintService.GetAllComplaintsAsync();

        return Ok(complaints);
    }
}
```

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Using MVC Controller for pure data endpoint unnecessarily | Use API controller |
| Returning full entity from API without thinking | Use DTO |
| Returning View from ControllerBase | Use Controller if View is needed |
| Forgetting route prefix for API | Use `[Route("api/...")]` |
| Not using proper HTTP status codes | Use Ok, Created, BadRequest, NotFound, Forbid |

---

## Interview Line

**MVC controllers return views for page rendering, while API controllers return data and HTTP status codes for clients such as AJAX or mobile apps.**

# 4. ApiController Attribute

## What

`[ApiController]` is an attribute that enables API-specific behavior in ASP.NET Core.

Example:

```csharp
[ApiController]
[Route("api/complaints")]
public class ComplaintsApiController : ControllerBase
{
}
```

---

## Why

`[ApiController]` helps with:

```text
Automatic model validation response
Better parameter binding behavior
API-specific conventions
Clear controller intention
```

---

## Automatic ModelState Behavior

In MVC controller, we often write:

```csharp
if (!ModelState.IsValid)
{
    return View(model);
}
```

In an API controller with `[ApiController]`, invalid model state can automatically return:

```text
400 Bad Request
```

with validation details.

---

## Smart Society Example

```csharp
[HttpPost]
public async Task<IActionResult> CreateComplaint(CreateComplaintApiDto dto)
{
    await _complaintService.CreateComplaintFromApiAsync(dto);

    return CreatedAtAction(nameof(GetComplaintById), new { id = dto.Title }, dto);
}
```

If DTO validation fails, `[ApiController]` can automatically return bad request.

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Forgetting `[ApiController]` | Add it for API controllers |
| Expecting View validation behavior in API | API returns validation response |
| Returning Razor views from API controller | Use MVC controller for views |
| Not using DTO validation | Add Data Annotations on DTO |
| Not understanding automatic 400 response | Know `[ApiController]` behavior |

---

## Interview Line

**The ApiController attribute enables API-focused behavior such as automatic model validation responses and improved request binding conventions.**

# 5. ControllerBase

## What

`ControllerBase` is a base class for API controllers that do not need view support.

Example:

```csharp
public class ComplaintsApiController : ControllerBase
{
}
```

---

## Why

API controllers usually return data, not views.

`ControllerBase` provides API-related methods such as:

```text
Ok
Created
CreatedAtAction
BadRequest
NotFound
NoContent
Unauthorized
Forbid
```

It does not include view rendering support.

---

## Controller Vs ControllerBase

| Base Class | Used For |
|---|---|
| `Controller` | MVC views + API possible |
| `ControllerBase` | API-only controllers |

---

## Smart Society API Example

```csharp
[Route("api/dashboard")]
[ApiController]
public class DashboardApiController : ControllerBase
{
    [HttpGet("summary")]
    public IActionResult GetSummary()
    {
        var summary = new
        {
            TotalComplaints = 120,
            PendingComplaints = 25,
            ResolvedComplaints = 80
        };

        return Ok(summary);
    }
}
```

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Using ControllerBase and returning View | Use Controller for MVC |
| Using Controller when only API is needed | ControllerBase is cleaner |
| Not using helper methods | Use Ok, NotFound, BadRequest |
| Returning raw strings for everything | Return structured DTOs |
| Ignoring HTTP status codes | Use proper response methods |

---

## Interview Line

**ControllerBase is used for API-only controllers and provides helper methods for returning HTTP responses without Razor view support.**

Resource examples:

```text

Users

Comments
```

---

## RESTful HTTP Methods

| HTTP Method | Meaning | Smart Society Example |
|---|---|---|
| GET | Read data | Get complaints |
| POST | Create data | Create complaint |
| PUT | Replace/update data | Update complaint status |
| PATCH | Partial update | Update only priority/status |
| DELETE | Delete/archive data | Archive complaint |

```text

GET /api/complaints/{id}
POST /api/complaints
PUT /api/complaints/{id}/status

```

---

## REST Awareness Rule

Use URLs as nouns/resources, not actions where possible.

Better:

```text
GET /api/complaints
PUT /api/complaints/5/status
```

Less REST-like:

```text
GET /api/getAllComplaints
POST /api/updateComplaintStatus
```

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Using GET to update data | Use PUT/PATCH/POST |
| Naming APIs as actions only | Prefer resource-based routes |
| Returning 200 for everything | Use proper status codes |
| Ignoring id in URL | Use resource identity in route |
| Thinking REST means only URL naming | REST includes method semantics and status codes |

---

## Interview Line

# 8. DTO Awareness

## What

DTO stands for:

```text
Data Transfer Object
```

A DTO is a class used to send or receive data through an API.

---

## Why

Do not expose database entities directly from APIs.

Entity may contain:

```text
Internal fields
Sensitive fields
Navigation properties
Audit data
User IDs
Large object graphs
```

DTOs allow us to control what data enters or leaves the API.

# 9. Creating Web API That Supports CRUD Operations Using EF

## What

Now we create API endpoints for complaint CRUD-style operations using EF through the existing service layer.

---

## Recommended Controller Location

Create folder:

```text
Controllers/Api
```

Create file:

```text
Controllers/Api/ComplaintsApiController.cs
```

---

## ComplaintsApiController

```csharp
using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.Mvc;
using SmartSociety.Web.DTOs;
using SmartSociety.Web.Interfaces;

namespace SmartSociety.Web.Controllers.Api
{
    [Route("api/complaints")]
    [ApiController]
    [Authorize]
    public class ComplaintsApiController : ControllerBase
    {
        private readonly IComplaintService _complaintService;

        public ComplaintsApiController(IComplaintService complaintService)
        {
            _complaintService = complaintService;
        }

        [HttpGet]
        [Authorize(Roles = "Admin")]
        public async Task<IActionResult> GetComplaints()
        {
            var complaints = await _complaintService.GetAllComplaintsAsync();

            var result = complaints.Select(c => new ComplaintListDto
            {
                ComplaintId = c.ComplaintId,
                Title = c.Title,
                Category = c.Category,
                Priority = c.Priority,
                Status = c.Status,
                CreatedDate = c.CreatedDate
            });

            return Ok(result);
        }

        [HttpGet("{id:int}")]
        public async Task<IActionResult> GetComplaintById(int id)
        {
            var complaint = await _complaintService.GetComplaintDetailsAsync(id);

            if (complaint == null)
            {
                return NotFound(new
                {
                    Message = "Complaint not found."
                });
            }

            var result = new ComplaintDetailsDto
            {
                ComplaintId = complaint.ComplaintId,
                Title = complaint.Title,
                Description = complaint.Description,
                Category = complaint.Category,
                Priority = complaint.Priority,
                Status = complaint.Status,
                CreatedDate = complaint.CreatedDate,
                AssignedToStaffName = complaint.AssignedToStaff?.FullName
            };

            return Ok(result);
        }

        [HttpPost]
        [Authorize(Roles = "Resident")]
        public async Task<IActionResult> CreateComplaint(CreateComplaintDto dto)
        {
            var userId = User.FindFirst(
                System.Security.Claims.ClaimTypes.NameIdentifier)?.Value;

            if (string.IsNullOrWhiteSpace(userId))
            {
                return Unauthorized();
            }

            await _complaintService.CreateComplaintFromApiAsync(dto, userId);

            return StatusCode(StatusCodes.Status201Created, new
            {
                Message = "Complaint created successfully."
            });
        }

        [HttpPut("{id:int}/status")]
        [Authorize(Roles = "Admin,Staff")]
        public async Task<IActionResult> UpdateStatus(
            int id,
            UpdateStatusDto dto)
        {
            var userId = User.FindFirst(
                System.Security.Claims.ClaimTypes.NameIdentifier)?.Value;

            if (string.IsNullOrWhiteSpace(userId))
            {
                return Unauthorized();
            }

            await _complaintService.UpdateComplaintStatusAsync(
                id,
                dto.NewStatus,
                userId,
                dto.Remarks);

            return Ok(new
            {
                Message = "Complaint status updated successfully."
            });
        }
    }
}
```

---

## Service Method For API Create

Add to `IComplaintService`:

```csharp
Task CreateComplaintFromApiAsync(CreateComplaintDto dto, string createdByUserId);
```

Implementation:

```csharp
public async Task CreateComplaintFromApiAsync(
    CreateComplaintDto dto,
    string createdByUserId)
{
    var complaint = new Complaint
    {
        Title = dto.Title,
        Description = dto.Description,
        Category = dto.Category,
        Priority = dto.Priority,
        Status = "New",
        CreatedByUserId = createdByUserId,
        CreatedDate = DateTime.UtcNow
    };

    await _complaintRepository.AddAsync(complaint);
    await _complaintRepository.SaveChangesAsync();
}
```

---

## API Response Status Codes

| Scenario | Status Code |
|---|---|
| Successful GET | `200 OK` |
| Successful create | `201 Created` |
| Successful update | `200 OK` or `204 NoContent` |
| Validation failure | `400 Bad Request` |
| Not logged in | `401 Unauthorized` |
| Logged in but not allowed | `403 Forbidden` |
| Record not found | `404 Not Found` |

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Returning entities directly | Return DTOs |
| No authorization on API | Add `[Authorize]` |
| No role restrictions | Use role-based authorization |
| Not handling missing record | Return NotFound |
| Using POST for every operation | Use proper HTTP methods |

# 14. Anti-Forgery Awareness With AJAX

## What

For MVC form POSTs, anti-forgery token protects against CSRF.

For AJAX calls that modify data, anti-forgery should also be considered.

---

## Why

Status update and assignment actions change server state.

They should not be vulnerable to forged requests.

---

## Token In View

```html
@Html.AntiForgeryToken()
```

This creates a hidden input like:

```html
<input name="__RequestVerificationToken" type="hidden" value="..." />
```

---

## Send Token In AJAX Header

```javascript
var token = $('input[name="__RequestVerificationToken"]').val();

$.ajax({
    url: "/api/complaints/5/status",
    method: "PUT",
    contentType: "application/json",
    headers: {
        "RequestVerificationToken": token
    },
    data: JSON.stringify({
        newStatus: "Resolved",
        remarks: "Issue fixed."
    }),
    success: function (response) {
        alert(response.message);
    }
});
```

---

## API Action

Depending on configuration, use:

```csharp
[ValidateAntiForgeryToken]
```

or configure anti-forgery validation strategy for APIs carefully.

---

## Important Note

For cookie-authenticated MVC apps using AJAX, anti-forgery is important.

For token-based APIs, a different approach may be used.

In this course:

```text
Understand anti-forgery awareness for AJAX state-changing requests.
```

---

## Common Mistake

| Mistake | Correction |
|---|---|
| Thinking AJAX does not need CSRF protection | State-changing AJAX needs protection |
| Not sending token header | Add token header |
| Using GET for status update | Use PUT/POST |
| Disabling anti-forgery blindly | Understand security impact |
| Mixing cookie auth and API without CSRF thinking | Plan security properly |

---

## Interview Line

**AJAX requests that modify data should consider anti-forgery protection, especially when using cookie-based authentication.**

# 22. Short Answers

1. Web API exposes HTTP endpoints that return data such as JSON.
2. It supports interactive UI, AJAX, mobile apps, and frontend integrations.
3. MVC Controller returns views; API Controller returns data and HTTP status codes.
4. It enables API-specific behavior such as automatic validation responses.
5. ControllerBase is a base class for API-only controllers.
6. JSON is a lightweight data format used for API communication.
7. REST designs APIs around resources and HTTP methods.
8. GET.
9. POST.
10. PUT or PATCH.
11. DTO means Data Transfer Object.
12. DTOs prevent exposing entity fields directly and shape API data safely.
13. Swagger/OpenAPI documents and tests APIs interactively.
14. AJAX calls the server without full page reload.
15. jQuery AJAX makes browser-side API calls simple.
16. Use `contentType: "application/json"` and `JSON.stringify`.
17. It inspects request URL, method, payload, response, headers, and status codes.
18. Postman tests API endpoints independently.
19. To prevent unauthorized data access or modification.
20. GET should not change server state; PUT represents update.

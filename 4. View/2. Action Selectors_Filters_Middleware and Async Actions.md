# 1. Understanding Action Selectors

## What

**Action selectors** help ASP.NET Core decide which action method should handle a request.

When a browser sends a request, ASP.NET Core uses:

```text
Route
Controller name
Action name
HTTP method
Action attributes
Parameters
```

to select the correct action method.

---

## Why

Many actions may have the same name but different purposes.

For example, complaint creation has two different operations:

```text
Open complaint form
Submit complaint form
```

Both can use the same action name:

```text
Create
```

But one handles GET request and the other handles POST request.

---

## Smart Society Example

```csharp
[HttpGet]
public IActionResult Create()
{
    return View();
}

[HttpPost]
public async Task<IActionResult> Create(ComplaintCreateViewModel model)
{
    if (!ModelState.IsValid)
    {
        return View(model);
    }

    await _complaintService.CreateComplaintAsync(model);

    TempData["SuccessMessage"] = "Complaint created successfully.";

    return RedirectToAction(nameof(Index));
}
```

Here, both methods are named `Create`, but ASP.NET Core knows which one to call based on the HTTP method.

---

## Request Mapping

| Request                   | Selected Action                                     |
| ------------------------- | --------------------------------------------------- |
| GET `/Complaints/Create`  | `[HttpGet] Create()`                                |
| POST `/Complaints/Create` | `[HttpPost] Create(ComplaintCreateViewModel model)` |

---

## Common Mistake

| Mistake                                                           | Correction                                                                      |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Creating only one `Create` action for form display and submission | Use separate GET and POST actions                                               |
| Forgetting `[HttpPost]` on submit action                          | Add `[HttpPost]`                                                                |
| Using wrong action parameters                                     | Match form data with ViewModel                                                  |
| Confusing routing with action selection                           | Routing finds action path; action selectors refine which method handles request |

---

## Interview Line

**Action selectors help ASP.NET Core choose the correct action method based on route, action name, HTTP method, attributes, and parameters.**

---

# 2. HttpGet

## What

`[HttpGet]` is used for actions that respond to HTTP GET requests.

GET requests are usually used to retrieve or display data.

---

## Why

GET should be used when we want to show a page or read information without changing data.

Examples:

```text
Open complaint form
View complaint list
View complaint details
Open dashboard
```

---

## Smart Society Examples

```csharp
[HttpGet]
public IActionResult Create()
{
    return View();
}
```

This action displays the complaint creation form.

```csharp
[HttpGet]
public async Task<IActionResult> Details(int id)
{
    var complaint = await _complaintService.GetComplaintByIdAsync(id);

    if (complaint == null)
    {
        return NotFound();
    }

    return View(complaint);
}
```

This action displays complaint details.

---

## GET Request Examples

```text
/Complaints
/Complaints/Create
/Complaints/Details/5
/Admin
/Dashboard
```

---

## Important Rule

GET should not change important application data.

For example, this is not good:

```text
GET /Complaints/Delete/5
```

because opening a URL should not delete data directly.

---

## Common Mistake

| Mistake                                      | Correction                           |
| -------------------------------------------- | ------------------------------------ |
| Using GET to submit or modify important data | Use POST/PUT/DELETE for data changes |
| Not marking display action with `[HttpGet]`  | Add `[HttpGet]` for clarity          |
| Passing sensitive data in query string       | Avoid sensitive data in URL          |
| Doing database update inside GET action      | GET should be safe and read-oriented |

---

## Interview Line

**HttpGet is used for actions that retrieve or display information, such as opening the complaint form or viewing complaint details.**

---

# 3. HttpPost

## What

`[HttpPost]` is used for actions that receive submitted data and usually change application state.

POST requests are commonly used for form submissions.

---

## Why

When a resident submits a complaint form, data must be sent to the server and processed.

This should use POST.

---

## Smart Society Example

```csharp
[HttpPost]
public async Task<IActionResult> Create(ComplaintCreateViewModel model)
{
    if (!ModelState.IsValid)
    {
        return View(model);
    }

    await _complaintService.CreateComplaintAsync(model);

    TempData["SuccessMessage"] = "Complaint created successfully.";

    return RedirectToAction(nameof(Index));
}
```

---

## What Happens In POST Create

```text
Resident fills complaint form
↓
Resident clicks Submit
↓
Browser sends POST request
↓
Model binding maps form data to ComplaintCreateViewModel
↓
Controller checks ModelState
↓
Controller calls ComplaintService
↓
Complaint is processed
↓
User is redirected to complaint list
```

---

## Post-Redirect-Get Pattern

After successful POST, redirect to another GET action.

```text
POST /Complaints/Create
↓
Redirect to /Complaints
↓
GET /Complaints
```

This avoids duplicate form submission on browser refresh.

---

## Common Mistake

| Mistake                                   | Correction                            |
| ----------------------------------------- | ------------------------------------- |
| Returning same view after successful POST | Use `RedirectToAction`                |
| Not checking `ModelState.IsValid`         | Validate model before processing      |
| Missing anti-forgery token in real forms  | Use anti-forgery protection           |
| Using GET for form submission             | Use POST for data-changing operations |

---

## Interview Line

**HttpPost is used for actions that receive submitted data and usually change application state, such as creating a new complaint.**

# 4. ActionName

## What

`[ActionName]` allows an action method to be exposed with a different action name in the route.

It means the method name in C# can be different from the action name used in the URL.

---

## Why

Sometimes we want a clearer method name in code but a different URL/action name.

Example:

```csharp
[ActionName("Details")]
public IActionResult ComplaintDetails(int id)
{
    return View();
}
```

This method name is:

```text
ComplaintDetails
```

But route action name is:

```text
Details
```

---

## Smart Society Example

```csharp
[ActionName("Details")]
public async Task<IActionResult> ComplaintDetails(int id)
{
    var complaint = await _complaintService.GetComplaintByIdAsync(id);

    if (complaint == null)
    {
        return NotFound();
    }

    return View("Details", complaint);
}
```

Now URL can still be:

```text
/Complaints/Details/5
```

---

## When To Use

Use `ActionName` when:

```text
You want a different public action name
You want clearer internal method names
You are avoiding method name conflicts
You are maintaining backward-compatible URLs
```

---

## Caution

Do not overuse `ActionName`.

It can confuse beginners because method name and route action name become different.

---

## Common Mistake

| Mistake                                         | Correction                                               |
| ----------------------------------------------- | -------------------------------------------------------- |
| Using ActionName unnecessarily                  | Use normal action names unless needed                    |
| Forgetting view name mismatch                   | Return correct view if method name differs               |
| Confusing C# method name with route action name | Understand that `[ActionName]` changes route action name |

---

## Interview Line

**ActionName allows an action method to be exposed with a different action name in routing, useful when method name and URL action name need to differ.**

# 5. Action Filters

## What

An **action filter** is code that runs before and/or after an action method executes.

In simple words:

```text
Action filter allows us to run common logic around controller actions.
```

---

## Why

Sometimes we need repeated logic around multiple actions.

Examples:

```text
Logging action execution
Auditing who accessed complaint details
Measuring execution time
Checking additional conditions
Adding common data to ViewBag
```

Instead of writing the same code in every action, we can use filters.

---

## Action Filter Flow

```text
Request comes to action
↓
Action filter runs before action
↓
Action method executes
↓
Action filter runs after action
↓
Response continues
```

---

## Smart Society Use Cases

| Use Case              | Filter Purpose                       |
| --------------------- | ------------------------------------ |
| Complaint audit       | Track who accessed complaint actions |
| Admin action tracking | Track admin assignment operations    |
| Execution timing      | Measure slow dashboard actions       |
| Common ViewBag setup  | Add common page information          |

---

## Simple Action Filter Example

```csharp
using Microsoft.AspNetCore.Mvc.Filters;

public class ComplaintAuditFilter : IActionFilter
{
    private readonly ILogger<ComplaintAuditFilter> _logger;

    public ComplaintAuditFilter(ILogger<ComplaintAuditFilter> logger)
    {
        _logger = logger;
    }

    public void OnActionExecuting(ActionExecutingContext context)
    {
        _logger.LogInformation(
            "Action executing: {ActionName}",
            context.ActionDescriptor.DisplayName);
    }

    public void OnActionExecuted(ActionExecutedContext context)
    {
        _logger.LogInformation(
            "Action executed: {ActionName}",
            context.ActionDescriptor.DisplayName);
    }
}
```

---

## Common Mistake

| Mistake                                  | Correction                             |
| ---------------------------------------- | -------------------------------------- |
| Writing repeated logging in every action | Use filter for cross-cutting logic     |
| Putting business logic inside filter     | Keep business logic in service         |
| Using filters when middleware is better  | Understand filter vs middleware scope  |
| Forgetting to register filter with DI    | Register filter if it has dependencies |

---

## Interview Line

**Action filters run before and after controller action execution and are useful for cross-cutting concerns like logging, auditing, and timing.**

---

# 6. Building Custom Action Filters

## What

A custom action filter is a filter created by us for project-specific needs.

---

## Why

In enterprise applications, we often need custom behavior.

For Smart Society, we may want to audit complaint actions.

Example:

```text
Who opened complaint details?
Which action was executed?
When was admin dashboard accessed?
Which user submitted complaint?
```

---

## Step 1: Create Filters Folder

Create folder:

```text
Filters
```

Create file:

```text
ComplaintAuditFilter.cs
```

---

## Step 2: Create Custom Filter

```csharp
using Microsoft.AspNetCore.Mvc.Filters;

namespace SmartSociety.Web.Filters
{
    public class ComplaintAuditFilter : IActionFilter
    {
        private readonly ILogger<ComplaintAuditFilter> _logger;

        public ComplaintAuditFilter(ILogger<ComplaintAuditFilter> logger)
        {
            _logger = logger;
        }

        public void OnActionExecuting(ActionExecutingContext context)
        {
            var actionName = context.ActionDescriptor.DisplayName;

            _logger.LogInformation(
                "Complaint audit started for action: {ActionName}",
                actionName);
        }

        public void OnActionExecuted(ActionExecutedContext context)
        {
            var actionName = context.ActionDescriptor.DisplayName;

            _logger.LogInformation(
                "Complaint audit completed for action: {ActionName}",
                actionName);
        }
    }
}
```

---

## Step 3: Register Filter In Program.cs

```csharp
builder.Services.AddScoped<ComplaintAuditFilter>();
```

---

## Step 4: Apply Filter To Controller

```csharp
using Microsoft.AspNetCore.Mvc;
using SmartSociety.Web.Filters;

[ServiceFilter(typeof(ComplaintAuditFilter))]
public class ComplaintsController : Controller
{
    // Actions here
}
```

---

## Alternative: Apply To Specific Action

```csharp
[ServiceFilter(typeof(ComplaintAuditFilter))]
public async Task<IActionResult> Details(int id)
{
    var complaint = await _complaintService.GetComplaintByIdAsync(id);

    if (complaint == null)
    {
        return NotFound();
    }

    return View(complaint);
}
```

---

## Smart Society Mapping

Use audit filter for:

```text
Complaint list access
Complaint details access
Complaint creation
Admin complaint actions
Staff status update actions later
```

---

## Common Mistake

| Mistake                                                 | Correction                        |
| ------------------------------------------------------- | --------------------------------- |
| Filter has constructor dependency but is not registered | Register filter in DI             |
| Applying audit filter to everything blindly             | Apply where useful                |
| Putting database save logic in filter                   | Keep business logic in service    |
| Logging sensitive data                                  | Do not log private/sensitive data |

---

## Interview Line

**A custom action filter allows us to run project-specific logic before and after actions. In Smart Society, I can use a custom audit filter to log complaint-related action execution.**

# 8. Exception Filter Concept

## What

Exception filters handle exceptions that occur during action execution.

---

## Why

Unexpected errors can happen.

Examples:

```text
Complaint not saved due to database issue
Invalid operation occurs during status update
Service throws an exception
Dashboard query fails
```

Exception filters can help handle certain action-level exceptions.

---

## Important Note

In ASP.NET Core, global exception handling is often handled using middleware such as:

```csharp
app.UseExceptionHandler("/Home/Error");
```

Exception filters are useful for MVC-specific scenarios, but middleware is usually preferred for global exception handling.

---

## Simple Concept Example

```csharp
using Microsoft.AspNetCore.Mvc;
using Microsoft.AspNetCore.Mvc.Filters;

public class CustomExceptionFilter : IExceptionFilter
{
    private readonly ILogger<CustomExceptionFilter> _logger;

    public CustomExceptionFilter(ILogger<CustomExceptionFilter> logger)
    {
        _logger = logger;
    }

    public void OnException(ExceptionContext context)
    {
        _logger.LogError(context.Exception, "An error occurred during action execution.");

        context.Result = new ViewResult
        {
            ViewName = "Error"
        };

        context.ExceptionHandled = true;
    }
}
```

---

## Smart Society Mapping

Use exception handling for:

```text
Unexpected complaint save failure
Unexpected dashboard error
Unexpected status update error
Invalid service operation
```

---

## Common Mistake

| Mistake                               | Correction                                         |
| ------------------------------------- | -------------------------------------------------- |
| Showing raw exception to user         | Show friendly error page                           |
| Swallowing exceptions silently        | Log exception details                              |
| Using exception filter for everything | Use global middleware for global errors            |
| Not handling known cases separately   | Use NotFound/BadRequest for expected invalid cases |

---

## Interview Line

**Exception filters can handle exceptions during MVC action execution, but global error handling in ASP.NET Core is commonly handled using exception-handling middleware.**

# 9. Middleware

## What

Middleware is a component in the ASP.NET Core request pipeline.

It processes HTTP requests and responses.

---

## Why

Before a request reaches the controller, the application may need to do many things:

```text
Handle errors
Redirect HTTP to HTTPS
Serve static files
Apply routing
Authenticate user
Authorize user
```

Middleware handles these pipeline-level tasks.

---

## Example In Program.cs

```csharp
app.UseHttpsRedirection();

app.UseStaticFiles();

app.UseRouting();

app.UseAuthorization();

app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");
```

---

## Smart Society Middleware Use

| Middleware           | Smart Society Purpose              |
| -------------------- | ---------------------------------- |
| Exception handling   | Friendly error page                |
| HTTPS redirection    | Secure requests                    |
| Static files         | CSS, JS, images                    |
| Routing              | Map URL to controller              |
| Authentication later | Identify logged-in user            |
| Authorization later  | Protect Resident/Admin/Staff pages |

---

## Real-Life Analogy

Think of entering a society building.

```text
Main gate security
Visitor register
Block selection
Lift access
Flat visit
Exit record
```

Middleware is like these checkpoints before reaching the final destination.

---

## Interview Line

**Middleware is a request-processing component in ASP.NET Core that runs before and after endpoint/controller execution as part of the HTTP pipeline.**

---

# 10. Middleware Pipeline

## What

The middleware pipeline is the ordered sequence of middleware components.

Each middleware can:

```text
Process request
Pass request to next middleware
Stop request
Process response on the way back
```

---

## Pipeline Example

```text
Request
↓
Exception Handling Middleware
↓
HTTPS Redirection Middleware
↓
Static Files Middleware
↓
Routing Middleware
↓
Authentication Middleware
↓
Authorization Middleware
↓
Endpoint / Controller Action
↓
Response
```

---

## Why Order Matters

Middleware order is important.

Example:

```text
UseRouting should run before UseAuthorization
UseAuthentication should run before UseAuthorization
UseStaticFiles should run before endpoint routing for static file serving
```

---

## Smart Society Future Pipeline

```csharp
if (!app.Environment.IsDevelopment())
{
    app.UseExceptionHandler("/Home/Error");
    app.UseHsts();
}

app.UseHttpsRedirection();

app.UseStaticFiles();

app.UseRouting();

app.UseAuthentication();

app.UseAuthorization();

app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");
```

---

## Common Mistake

| Mistake                                           | Correction                                            |
| ------------------------------------------------- | ----------------------------------------------------- |
| Changing middleware order randomly                | Middleware order matters                              |
| Placing UseAuthorization before UseAuthentication | Authentication should come before authorization       |
| Forgetting UseStaticFiles                         | CSS/JS may not load                                   |
| Thinking middleware is same as controller         | Middleware is pipeline-level, controller is MVC-level |

---

## Interview Line

**The middleware pipeline is the ordered sequence of components that process requests before they reach the controller and responses before they return to the browser.**

---

# 11. Use, Run, Map Awareness

## What

ASP.NET Core provides methods to build middleware flow:

```text
Use
Run
Map
```

---

# Use

## Meaning

`Use` adds middleware that can call the next middleware.

Conceptually:

```csharp
app.Use(async (context, next) =>
{
    // Code before next middleware

    await next();

    // Code after next middleware
});
```

## Simple Meaning

```text
Use can pass request forward and also process response on the way back.
```

---

# Run

## Meaning

`Run` adds terminal middleware.

It does not call next middleware.

```csharp
app.Run(async context =>
{
    await context.Response.WriteAsync("Request ended here.");
});
```

## Simple Meaning

```text
Run ends the pipeline.
```

---

# Map

## Meaning

`Map` branches the pipeline based on a path.

```csharp
app.Map("/health", healthApp =>
{
    healthApp.Run(async context =>
    {
        await context.Response.WriteAsync("Smart Society app is running.");
    });
});
```

## Simple Meaning

```text
Map creates a separate branch for a specific URL path.
```

---

## Smart Society Examples

| Method | Possible Use                               |
| ------ | ------------------------------------------ |
| `Use`  | Logging request before next middleware     |
| `Run`  | Simple terminal response for test endpoint |
| `Map`  | Separate `/health` or `/status` branch     |

---

## Common Mistake

| Mistake                                      | Correction                            |
| -------------------------------------------- | ------------------------------------- |
| Using Run in middle of pipeline accidentally | Run can stop further processing       |
| Not calling `next()` inside Use              | Request may not continue              |
| Using Map when normal route is enough        | Use Map for special pipeline branches |
| Writing too much custom middleware early     | Use built-in middleware first         |

---

## Interview Line

**Use adds middleware that can call the next component, Run adds terminal middleware, and Map creates a branch in the pipeline based on a request path.**

---

# 12. Middleware Vs Filter

## What

Middleware and filters both run during request processing, but they work at different levels.

---

## Comparison

| Area                    | Middleware                                    | Filter                                      |
| ----------------------- | --------------------------------------------- | ------------------------------------------- |
| Level                   | Application pipeline                          | MVC pipeline                                |
| Runs Before Controller? | Yes                                           | Yes, but after MVC routing/action selection |
| Works For               | All requests                                  | MVC controllers/actions                     |
| Good For                | Global concerns                               | MVC/action-specific concerns                |
| Examples                | HTTPS, static files, auth, exception handling | Action logging, validation, audit           |
| Configured In           | `Program.cs`                                  | Attributes / MVC options / DI               |

---

## Smart Society Example

| Requirement                    | Better Choice |
| ------------------------------ | ------------- |
| Serve CSS/JS files             | Middleware    |
| Enforce HTTPS                  | Middleware    |
| Global error page              | Middleware    |
| Authenticate user              | Middleware    |
| Log complaint action execution | Action filter |
| Audit admin action             | Action filter |
| Add common ViewBag data        | Filter        |

---

## Simple Explanation

```text
Middleware works before MVC action is selected.
Filters work around MVC controller/action execution.
```

---

## Common Mistake

| Mistake                                        | Correction                     |
| ---------------------------------------------- | ------------------------------ |
| Using filters for global HTTP pipeline tasks   | Use middleware                 |
| Using middleware for action-specific MVC logic | Use filters                    |
| Thinking both are same                         | Understand pipeline level      |
| Putting business logic in both                 | Keep business logic in service |

---

## Interview Line

**Middleware runs at the application request pipeline level, while filters run within the MVC pipeline around controller/action execution.**

# 13. Asynchronous Action Methods

## What

An asynchronous action method allows long-running operations to run without blocking the request thread.

In ASP.NET Core, async actions commonly return:

```csharp
Task<IActionResult>
```

---

## Why

Web applications often perform I/O operations such as:

```text
Database queries
File upload
API calls
Email sending
Reading external service data
```

These operations should be asynchronous where possible.

---

## Smart Society Examples

Use async for:

```text
Get complaint list
Get complaint details
Create complaint
Update complaint status
Load dashboard summary
```

---

## Example

```csharp
public async Task<IActionResult> Index()
{
    var complaints = await _complaintService.GetAllComplaintsAsync();

    return View(complaints);
}
```

---

## Flow

```text
Request reaches Index action
↓
Action calls async service method
↓
await waits without blocking thread
↓
Service returns data
↓
Controller returns view
```

---

## Common Mistake

| Mistake                                    | Correction                                      |
| ------------------------------------------ | ----------------------------------------------- |
| Blocking async code using `.Result`        | Use `await`                                     |
| Using async without await                  | Remove async or await actual async call         |
| Making CPU-heavy work async unnecessarily  | Async is mainly useful for I/O-bound operations |
| Forgetting Task<IActionResult> return type | Use `Task<IActionResult>` for async actions     |

---

## Interview Line

**Asynchronous action methods use async and await to perform I/O operations like database calls without blocking the request thread, improving scalability.**

---

# 14. Task<IActionResult>

## What

`Task<IActionResult>` means the action will complete asynchronously and eventually return an `IActionResult`.

Example:

```csharp
public async Task<IActionResult> Details(int id)
{
    var complaint = await _complaintService.GetComplaintByIdAsync(id);

    if (complaint == null)
    {
        return NotFound();
    }

    return View(complaint);
}
```

---

## Why

When calling asynchronous service or database methods, the controller action should also be async.

For example:

```text
GetComplaintByIdAsync
GetAllComplaintsAsync
CreateComplaintAsync
```

These return tasks, so controller awaits them.

---

## Smart Society Mapping

| Action               | Return Type           | Why                     |
| -------------------- | --------------------- | ----------------------- |
| `Index()`            | `Task<IActionResult>` | Loads complaint list    |
| `Details(int id)`    | `Task<IActionResult>` | Loads complaint details |
| `Create(model)` POST | `Task<IActionResult>` | Saves complaint later   |
| `Dashboard()`        | `Task<IActionResult>` | Loads dashboard counts  |

---

## Common Mistake

| Mistake                                     | Correction                   |
| ------------------------------------------- | ---------------------------- |
| Calling async method without await          | Use await                    |
| Returning `IActionResult` while using await | Use `Task<IActionResult>`    |
| Mixing sync and async database calls        | Prefer async EF Core methods |
| Using `.Wait()` or `.Result`                | Avoid blocking calls         |

---

## Interview Line

**Task<IActionResult> is used when an MVC action runs asynchronously and will eventually return a response such as View, Redirect, NotFound, or Json.**

---

# 15. async / await

## What

`async` and `await` are C# keywords used for asynchronous programming.

---

## Meaning

```text
async marks a method as asynchronous.
await waits for an asynchronous operation to complete without blocking the thread.
```

---

## Example

```csharp
public async Task<IActionResult> Index()
{
    var complaints = await _complaintService.GetAllComplaintsAsync();

    return View(complaints);
}
```

## Explanation

| Code                      | Meaning                                               |
| ------------------------- | ----------------------------------------------------- |
| `async`                   | Method contains asynchronous operation                |
| `Task<IActionResult>`     | Method returns a task that will produce IActionResult |
| `await`                   | Waits for service method to complete                  |
| `GetAllComplaintsAsync()` | Async service operation                               |
| `return View(complaints)` | Returns view after data is available                  |

---

## Smart Society Use Cases

```text
Loading complaints from database
Saving complaint
Updating complaint status
Loading dashboard summary
Fetching comments and attachments
```

---

## Common Mistake

| Mistake                             | Correction                                    |
| ----------------------------------- | --------------------------------------------- |
| Using async everywhere without need | Use async for real async operations           |
| Forgetting await                    | Await async calls                             |
| Blocking async code                 | Avoid `.Result` and `.Wait()`                 |
| Not following naming convention     | Async methods should usually end with `Async` |

---

## Interview Line

**async and await allow ASP.NET Core actions to perform asynchronous operations such as database calls without blocking server threads.**

namespace SmartSociety.Web.Controllers

            _complaintService = complaintService;
            _logger = logger;
        }

        [HttpGet]

            return View(complaints);
        }

        [HttpGet]
        public IActionResult Create()
        {
            ViewBag.PageTitle = "Raise New Complaint";

            return View();
        }

        [HttpPost]
        public async Task<IActionResult> Create(ComplaintCreateViewModel model)
        {
            if (!ModelState.IsValid)
            {
                ViewBag.PageTitle = "Raise New Complaint";

                return View(model);
            }

            await _complaintService.CreateComplaintAsync(model);

            TempData["SuccessMessage"] = "Complaint created successfully.";

            return RedirectToAction(nameof(Index));
        }

        [HttpGet]
        public async Task<IActionResult> Details(int id)
        {
            if (id <= 0)
            {
                return BadRequest("Invalid complaint id.");
            }

            var complaint = await _complaintService.GetComplaintByIdAsync(id);

            if (complaint == null)
            {
                return NotFound();
            }

            return View(complaint);
        }
    }
}

using Microsoft.AspNetCore.Mvc.Filters;

namespace SmartSociety.Web.Filters
{
    public class ComplaintAuditFilter : IActionFilter
    {
        private readonly ILogger<ComplaintAuditFilter> _logger;

        public ComplaintAuditFilter(ILogger<ComplaintAuditFilter> logger)
        {
            _logger = logger;
        }

        public void OnActionExecuting(ActionExecutingContext context)
        {
            _logger.LogInformation(
                "Audit started for action: {ActionName}",
                context.ActionDescriptor.DisplayName);
        }

        public void OnActionExecuted(ActionExecutedContext context)
        {
            _logger.LogInformation(
                "Audit completed for action: {ActionName}",
                context.ActionDescriptor.DisplayName);
        }
    }
}

# 18. Common Mistakes

| Mistake                              | Why It Is Wrong                           | Correction                                               |
| ------------------------------------ | ----------------------------------------- | -------------------------------------------------------- |
| Not separating GET and POST actions  | Form display and submission are different | Use `[HttpGet]` and `[HttpPost]`                         |
| Using GET for data changes           | Unsafe and semantically wrong             | Use POST for create/update operations                    |
| Returning View after successful POST | Can duplicate form submission             | Use RedirectToAction                                     |
| Writing audit logic in every action  | Repeated code                             | Use action filter                                        |
| Putting business rules in filter     | Wrong responsibility                      | Keep business rules in service                           |
| Confusing middleware and filters     | They run at different levels              | Middleware is app pipeline, filters are MVC/action level |
| Using `Run` too early                | It stops pipeline                         | Use carefully                                            |
| Forgetting `await`                   | Async operation may not execute correctly | Use `await`                                              |
| Blocking async code with `.Result`   | Can hurt scalability                      | Use async/await                                          |
| Forgetting to register filter        | Runtime DI error                          | Register filter in Program.cs                            |

# 21. Short Answers

1. Action selectors help ASP.NET Core choose the correct action method based on route, HTTP method, attributes, and parameters.
2. `[HttpGet]` handles requests that retrieve or display information.
3. `[HttpPost]` handles submitted data and operations that usually change application state.
4. GET displays the form, while POST processes the submitted form data.
5. `[ActionName]` exposes a method with a different action name in routing.
6. An action filter runs before and/or after an action method executes.
7. It runs around MVC action execution.
8. A custom action filter is useful for repeated cross-cutting logic such as auditing or action logging.
9. Authorization filters check whether the user is allowed to access a controller/action.
10. Exception filters handle exceptions during MVC action execution.
11. Middleware is a request-processing component in the ASP.NET Core pipeline.
12. The middleware pipeline is the ordered sequence of middleware components that process requests and responses.
13. Middleware order matters because each component runs in sequence and can affect the next component.
14. Middleware runs at application pipeline level; filters run around MVC controller/action execution.
15. `Use` adds middleware that can call the next middleware.
16. `Run` adds terminal middleware that ends the pipeline.
17. `Map` creates a pipeline branch for a specific path.
18. Async actions avoid blocking threads during I/O operations like database calls.
19. `Task<IActionResult>` means the action completes asynchronously and eventually returns an MVC response.
20. `async` marks a method asynchronous; `await` waits for an async operation without blocking the thread.

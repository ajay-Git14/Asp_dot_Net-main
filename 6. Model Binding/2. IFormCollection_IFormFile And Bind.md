# ASP.NET Core MVC Practical: IFormCollection, IFormFile, Bind Attribute and TryUpdateModelAsync

## Goal

Create a simple ASP.NET Core MVC practical where the learner understands advanced form binding, manual form reading, file upload basics, and safe update patterns.

This practical is connected with the **Smart Society** project.

In Smart Society, residents can raise complaints, upload complaint images, staff can upload completion proof, and the application must prevent residents from changing protected fields like `Status` or `AssignedStaff` by form tampering.

- IFormFile Model Binder

- Safe Update Patterns

# 1. What Is IFormCollection?

`IFormCollection` represents the posted form data.

It allows us to manually read values from the form.

Example:

```csharp
string title = form["Title"];
string description = form["Description"];
```

This works, but it is manual.

That means we have to read every form field by name.

---

## Simple Meaning

Think of `IFormCollection` like a bag of form values.

When the user submits a form, ASP.NET Core puts all submitted fields inside this bag.

You can open the bag and manually read each value.

---

## Example

HTML form:

```html
<input name="Title" />
<input name="Description" />
```

Controller:

```csharp
[HttpPost]
public IActionResult Save(IFormCollection form)
{
    string title = form["Title"];
    string description = form["Description"];

    return Content(title + " - " + description);
}
```

---

# 2. Problem With Manual Form Reading

Manual form reading works, but it has some problems.

```csharp
string title = form["Title"];
string description = form["Description"];
string priority = form["Priority"];
```

Problems:

- More code
- Easy to make spelling mistakes
- No clean model structure
- Validation becomes difficult
- Not suitable for bigger applications

---

# 3. Strongly Typed Binding Is Preferred

Instead of manually reading form values, ASP.NET Core MVC can directly bind form data to a model object.

Model:

```csharp
public class Complaint
{
    public string Title { get; set; }
    public string Description { get; set; }
}
```

Controller:

```csharp
[HttpPost]
public IActionResult Create(Complaint complaint)
{
    return View();
}
```

Now ASP.NET Core automatically maps:

```text
<input name="Title" />       -> complaint.Title
<input name="Description" /> -> complaint.Description
```

This is called **Model Binding**.

---

## IFormCollection vs Strongly Typed Binding

| IFormCollection | Strongly Typed Binding |
|---|---|
| Manual reading | Automatic binding |
| More code | Less code |
| Easy to make mistakes | Cleaner and safer |
| Useful for special cases | Preferred for normal forms |
| Validation is manual | Works with ModelState |

# 4. What Is IFormFile?

`IFormFile` is used to receive uploaded files in ASP.NET Core MVC.

Example:

```csharp
public async Task<IActionResult> Create(IFormFile imageFile)
{
    // save file here
}
```

It is commonly used for:

- Profile image upload
- Complaint image upload
- Document upload
- Completion proof upload

---

# 5. Important: enctype="multipart/form-data"

For file upload, your form must contain this:

```html
enctype="multipart/form-data"
```

Without this, file upload will not work properly.

Correct form:

```html
<form method="post" enctype="multipart/form-data">
    <input type="file" name="imageFile" />
    <button type="submit">Upload</button>
</form>
```

Wrong form:

```html
<form method="post">
    <input type="file" name="imageFile" />
    <button type="submit">Upload</button>
</form>
```

In the wrong form, the file may not reach the controller properly.

---

# 6. What Is Bind Attribute?

`[Bind]` tells ASP.NET Core MVC which properties are allowed during model binding.

Example:

```csharp
[HttpPost]
public IActionResult Create([Bind("Title,Description,Priority")] Complaint complaint)
{
    return View();
}
```

Only these properties are allowed:

```text
Title
Description
Priority
```

Other properties like `Status`, `AssignedStaff`, or `CreatedAt` will not be taken from the form.

---

# 7. What Is Overposting?

Overposting means the user sends extra fields that should not be updated.

Example:

A normal resident complaint form should send only:

```text
Title
Description
Priority
```

But a smart user can inspect the browser and add hidden fields:

```html
<input type="hidden" name="Status" value="Closed" />
<input type="hidden" name="AssignedStaff" value="Admin" />
```

If your controller blindly accepts the full entity, these protected values may also get updated.

That is dangerous.

---

## Smart Society Example

A resident should be allowed to update:

```text
Title
Description
Priority
```

A resident should not be allowed to update:

```text
Status
AssignedStaff
CompletionProofPath
```

Because these fields should be controlled by admin or staff.

---

# 8. What Is TryUpdateModelAsync?

`TryUpdateModelAsync` updates an existing object using form data.

The important part is this:

```csharp
await TryUpdateModelAsync(
    complaint,
    "",
    c => c.Title,
    c => c.Description,
    c => c.Priority
);
```

Only these fields are updated:

```text
Title
Description
Priority
```

Even if the form sends `Status=Closed`, it will not update `Status`.

# 11. Create Complaints Controller

Create this file:

```text
Controllers/ComplaintsController.cs
```

Code:

```csharp
using Microsoft.AspNetCore.Mvc;
using SmartSocietyDemo.Models;

namespace SmartSocietyDemo.Controllers
{
    public class ComplaintsController : Controller
    {
        private static List<Complaint> _complaints = new List<Complaint>();
        private static int _nextId = 1;

        private readonly IWebHostEnvironment _environment;

        public ComplaintsController(IWebHostEnvironment environment)
        {
            _environment = environment;
        }

        public IActionResult Index()
        {
            return View(_complaints);
        }

        public IActionResult ManualCreate()
        {
            return View();
        }

        [HttpPost]
        [ValidateAntiForgeryToken]
        public async Task<IActionResult> ManualCreate(IFormCollection form)
        {
            var imageFile = form.Files["ImageFile"];

            var complaint = new Complaint
            {
                Id = _nextId++,
                Title = form["Title"].ToString(),
                Description = form["Description"].ToString(),
                Category = form["Category"].ToString(),
                Priority = form["Priority"].ToString(),
                Status = "Pending",
                AssignedStaff = "Not Assigned",
                CreatedAt = DateTime.Now,
                ImagePath = await SaveFileAsync(imageFile)
            };

            _complaints.Add(complaint);

            return RedirectToAction(nameof(Index));
        }

        public IActionResult Create()
        {
            return View();
        }

        [HttpPost]
        [ValidateAntiForgeryToken]
        public async Task<IActionResult> Create(
            [Bind("Title,Description,Category,Priority")] Complaint complaint,
            IFormFile? imageFile)
        {
            if (!ModelState.IsValid)
            {
                return View(complaint);
            }

            complaint.Id = _nextId++;
            complaint.Status = "Pending";
            complaint.AssignedStaff = "Not Assigned";
            complaint.CreatedAt = DateTime.Now;
            complaint.ImagePath = await SaveFileAsync(imageFile);

            _complaints.Add(complaint);

            return RedirectToAction(nameof(Index));
        }

        public IActionResult Edit(int id)
        {
            var complaint = _complaints.FirstOrDefault(c => c.Id == id);

            if (complaint == null)
            {
                return NotFound();
            }

            return View(complaint);
        }

        [HttpPost]
        [ValidateAntiForgeryToken]
        public async Task<IActionResult> Edit(int id)
        {
            var complaint = _complaints.FirstOrDefault(c => c.Id == id);

            if (complaint == null)
            {
                return NotFound();
            }

            bool updated = await TryUpdateModelAsync(
                complaint,
                "",
                c => c.Title,
                c => c.Description,
                c => c.Category,
                c => c.Priority
            );

            if (updated)
            {
                return RedirectToAction(nameof(Index));
            }

            return View(complaint);
        }

        public IActionResult UploadProof(int id)
        {
            var complaint = _complaints.FirstOrDefault(c => c.Id == id);

            if (complaint == null)
            {
                return NotFound();
            }

            return View(complaint);
        }

        [HttpPost]
        [ValidateAntiForgeryToken]
        public async Task<IActionResult> UploadProof(int id, IFormFile? proofFile)
        {
            var complaint = _complaints.FirstOrDefault(c => c.Id == id);

            if (complaint == null)
            {
                return NotFound();
            }

            if (proofFile == null || proofFile.Length == 0)
            {
                ModelState.AddModelError("", "Please select a proof image.");
                return View(complaint);
            }

            complaint.CompletionProofPath = await SaveFileAsync(proofFile);
            complaint.Status = "Resolved";

            return RedirectToAction(nameof(Index));
        }

        private async Task<string?> SaveFileAsync(IFormFile? file)
        {
            if (file == null || file.Length == 0)
            {
                return null;
            }

            string uploadsFolder = Path.Combine(_environment.WebRootPath, "uploads");

            if (!Directory.Exists(uploadsFolder))
            {
                Directory.CreateDirectory(uploadsFolder);
            }

            string fileExtension = Path.GetExtension(file.FileName);
            string fileName = $"{Guid.NewGuid()}{fileExtension}";
            string filePath = Path.Combine(uploadsFolder, fileName);

            using FileStream stream = new FileStream(filePath, FileMode.Create);
            await file.CopyToAsync(stream);

            return "/uploads/" + fileName;
        }
    }
}
```

# 25. Common Mistakes

## Mistake 1: Missing enctype

Wrong:

```html
<form method="post">
```

Correct:

```html
<form method="post" enctype="multipart/form-data">
```

---

## Mistake 2: File Input Name Does Not Match Controller Parameter

View:

```html
<input type="file" name="imageFile" />
```

Controller:

```csharp
public IActionResult Create(IFormFile imageFile)
```

Both names should match.

---

## Mistake 3: Binding Full Entity Directly

Avoid this in sensitive forms:

```csharp
public IActionResult Edit(Complaint complaint)
```

This can allow overposting if the user sends extra fields.

Better:

```csharp
await TryUpdateModelAsync(
    complaint,
    "",
    c => c.Title,
    c => c.Description,
    c => c.Priority
);
```

---

## Mistake 4: Trusting File Name From User

Do not directly save uploaded file using original file name.

Avoid:

```csharp
string fileName = file.FileName;
```

Better:

```csharp
string fileName = $"{Guid.NewGuid()}{Path.GetExtension(file.FileName)}";
```

This prevents filename conflicts and reduces risk.

# 26. Interview Line

`IFormCollection` is used for manual form reading, but strongly typed model binding is preferred in MVC because it is cleaner and works better with validation. `IFormFile` is used for file uploads and requires `multipart/form-data`. `[Bind]` and `TryUpdateModelAsync` help protect the application from overposting by allowing only selected properties to be bound or updated.

# 30. Real Project Recommendation

For real Smart Society development, prefer this pattern:

```text
ViewModel -> Validate -> Find Existing Entity -> Copy Allowed Fields -> Save
```

Best practice:

- Do not bind database entity directly from user form
- Use separate Create and Edit ViewModels
- Always validate file type and file size
- Store uploaded files safely
- Keep admin-only fields away from resident forms
- Use authorization for staff/admin actions

Example protected fields:

```text
Status
AssignedStaff
AdminRemarks
CompletionProofPath
ClosedDate
```

These fields should be updated only by authorized admin or staff.
